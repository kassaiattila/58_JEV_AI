# User guide

**Valid from:** 2026-10-28 (v1.58.0). **Audience:** people who use the interface.

## Plain-language summary

The interface runs in your browser and connects to a local service running on your own computer. There is no login: every change is recorded under the name chosen in the **Who is working?** (*Ki dolgozik?*) field in the header. The daily work is the list of cases (*ügyek*): each case is one matter of a process (the documents of a folder, a month's reconciliation, a quote), started from **New case** (*Új ügy*). A case's documents or emails are handled together as a document batch (*iratköteg*; until 2026-10-28 a work package, *munkacsomag*). You work on a batch in three stages: in **Processing** (*Feldolgozás*) you check the processing settings and start a run (the system recognises each document's type itself); in **Review** (*Ellenőrzés*) you resolve the to-dos and correct wrong data next to an image of the document; in **Result** (*Eredmény*) you download the tables and approve the live run. A paid AI call is always started by a person, after confirmation, with the cost budget shown in advance.

## 1. A few terms first

The interface starts in Hungarian; the **HU / EN** buttons in the header switch it to English (section 2.2). This guide quotes the English labels, and on first mention gives the Hungarian label in italics, for example **Who is working?** (*Ki dolgozik?*). The full vocabulary is in the [glossary](../GLOSSARY.md). For this guide, these terms are enough:

| Term | Meaning |
|---|---|
| Case (*ügy*) | One matter of a process, followed from start to finish: its steps, its documents, its decisions and its cost. The daily work list is the list of cases. |
| Document batch (*iratköteg*; until 2026-10-28 *munkacsomag*) | Documents or emails from one source, handled together inside a case's step. It has one set of processing settings and can have several runs. The English interface called it a work package until 2026-10-28; the code still does. |
| Sub-case (*részügy*) | A case of another process that a step of a multi-step process runs and waits for (section 4.1). |
| Processing settings (*feldolgozási beállítások*) | The recipe and processing path, Azure recognition, reuse of earlier answers and, for emails, task proposals. The recipe determines supported files; PDF documents use type recognition, while Word, Excel, TXT and CSV use source-bound fact extraction. |
| Run (*futás*) | Processing the batch's items once. It is either a **trial run** (it can be viewed and downloaded but not released) or a **live run** (valid once approved). |
| To-do (*teendő*) | A reason on an item that needs a person to check it, for example ‘Uncertain value: Gross amount (probability 0.58)’ (*Bizonytalan érték: Bruttó összeg (valószínűség 0,58)*). Each reason is resolved separately. |
| Worker (*feldolgozó*) | The background program that processes the items of runs one by one. If it is not running, runs wait. |
| Local service (*helyi szolgáltatás*) | The program that serves the interface and accepts requests only from this computer. |
| JEV and GPT | The two paid AI services. JEV gives probabilities for closed questions (which value is the right one, whether a statement is true); GPT (OpenAI's text-generation model) reads data out of text. |

## 2. Starting up and the parts of the screen

1. The start script launches the local service and the worker in the background (the exact command is in the Technical details). You only need to start it once: closing the browser or the tab does not stop it, and does not interrupt work in progress either.
2. Open http://127.0.0.1:8930/ in your browser. The address works only on this computer.
3. The header holds the two main parts at its left: **Cases** (*Ügyek*) for daily work, and **Settings** (*Beállítások*). An address no page has says so (‘There is no such page’, *Nincs ilyen lap*). Every page is built the same way: its crumbs, its title with the page's main action at the right end of the title row, then its content; a form's buttons stand at its foot on the right, **Cancel** (*Mégse*) first; an action that cannot be undone asks for confirmation in a small card under its button.
4. On the left of the header is the worker badge: ‘Worker running’ (*Feldolgozó fut*) or ‘Worker not running’ (*Feldolgozó nem fut*), followed by ‘N items waiting’ (*N tétel vár*) when work is queued. A red ‘The local service is not reachable’ (*A helyi szolgáltatás nem érhető el*) badge means the service has stopped (see section 11). Next to it are the **HU / EN** language buttons.
5. On the right of the header is the **Who is working?** field.

### 2.1 Who is working?

- Every action that changes something is recorded under the selected name: creating and managing a batch, processing settings, starting and stopping a run, corrections, resolving to-dos, approval, task-proposal decisions, mailbox downloads and **Back up now** (*Mentés most*). This way you can always see later who did what. Without a name, the service rejects these actions (‘enter your name in the “Who is working?” field at the top…’ (*add meg a neved fent a „Ki dolgozik?” mezőben…*)).
- If the list under Settings › Users (*Felhasználók*) is not empty, the field works as a picker (‘Choose your name’ (*Válaszd ki a neved*)). Until a name is selected, ‘Select your name before making changes.’ (*Módosítás előtt válaszd ki a neved.*) is shown. Only a name on the list is accepted.
- If the list is empty, you can type any name. After **Save** (*Mentés*), ‘Remembered’ (*Megjegyezve*) appears; the **Add users** (*Felhasználók felvétele*) link takes you to the name list.
- The name is remembered in this browser and applies to every open tab. If you change it in one tab, the other tabs show the new name too.
- The name is not a permission and has no password behind it: anyone can choose any name.
- Once a name is selected, a **My work today** (*Mai munkám*) link appears next to the field (section 9).

### 2.2 Language

The **HU / EN** buttons switch the interface labels, and what the system makes for you from then on follows the same language (since `v1.63.0`): a download's headers, sheet names and labels (Excel and CSV), and the content-based file names (the type's word, the review subfolder and the manifest; section 8). Document data and original file names do not change, and unsaved corrections are kept. The choice is remembered in this browser. You can set the same on the Settings › Appearance and language (*Megjelenés és nyelv*) page.

## 3. The list of every document batch

Daily work is in the case list (**Cases**); a case's batch opens inside its step, and the batch's page leads back to its case and step. **All document batches** (*Minden iratköteg*), under Settings › Operations › **Earlier work** (*Üzemeltetés › Korábbi munkák*), lists the batches that belong to no case, to find an earlier one: since 2026-10-28 the batches made before are taken over as cases of the Documents and the Emails from a mailbox processes, so it holds the hidden ones and those no process takes. New work starts as a case (section 4.2). By default the newest batch comes first. The columns are: ‘Name’ (*Név*), ‘Next step’ (*Következő lépés*), ‘Last run’ (*Utolsó futás*), ‘Item’ (*Tétel*), ‘Open to-dos’ (*Nyitott teendő*), ‘Source’ (*Forrás*), ‘Processing’ (*Feldolgozás*), ‘Assignee’ (*Felelős*), ‘Last activity’ (*Utolsó tevékenység*) and ‘Created’ (*Létrehozva*). ‘Next step’ (for example ‘Start trial run’ (*Próbafutás indítása*), ‘Review: 3 to-dos’ (*Ellenőrzés: 3 teendő*) or ‘Approval’ (*Jóváhagyás*)) takes you to the matching stage of the batch. ‘Open to-dos’ counts the to-dos of the latest run and takes you to Review. ‘Older runs to supersede’ (*Leváltható régi futás*) counts the batch's older live runs that a later live run repeated and that you can supersede; it takes you to the batch's Processing section, where they are listed. A run you stopped after an earlier finished run does not hide that run: ‘Next step’, ‘Open to-dos’ and the Review and Result tabs follow the earlier run, while ‘Last run’ still shows the stopped one. The list refreshes itself; it always answers at once, and while it is being brought up to date after a change, ‘Updating…’ (*Frissül…*) is shown below it for a few seconds.

Tables work the same way in every list:

- **Search:** the ‘Search all columns…’ (*Keresés az összes oszlopban…*) field ignores both letter case and accents (‘szamla’ finds ‘Számla’, Hungarian for ‘invoice’).
- **Sorting:** click a column header (ascending, descending, off). Shift + click adds a further sort level.
- **Filtering:** use the funnel icon in the column header. Text columns offer ‘Contains’ (*Tartalmazza*), number and date columns ‘At least’ (*Legalább*) / ‘At most’ (*Legfeljebb*), and columns with a fixed set of values offer checkboxes; everywhere you can also choose ‘all / empty only / filled only’ (*mind / csak üres / csak kitöltött*). Active filters appear as tags above the table. Remove them one by one with ×, or all at once with **Clear all filters** (*Minden szűrő törlése*).
- **Only my document batches** (*Csak a saját kötegeim*): shows only the batches you are the owner of. You need to choose a name first.
- **Hidden batches too** (*Elrejtett kötegek is*): also shows hidden batches, with a ‘Batch’ (*Köteg*) column showing their state.
- **Columns (x/y)** (*Oszlopok (x/y)*): turn on hidden columns here, for example ‘Open to-dos incl. earlier runs’ (*Nyitott teendő a korábbi futásokkal*) or ‘Source location’ (*Forrás helye*). **Reset** (*Alaphelyzet*) restores the original columns. The choice is remembered per table in this browser.
- **Column width:** drag the right edge of a column header to make the column narrower or wider; the text wraps inside the cell. With the keyboard, move to the edge with Tab and use the left and right arrows. From the first change, only the column you drag changes width and the table grows or shrinks with it. **Reset column widths** (*Oszlopszélességek alaphelyzetbe*, in the **Columns** menu) returns the automatic widths. The widths are remembered per table in this browser. Faint lines separate the rows and the columns of every table.
- **Paging:** at the bottom you find ‘1–100 of N rows’ (*1–100 / N sor*), the number of rows per page (50, 100, 250, 500) and the page buttons.

### 3.1 Download

Every table has a **Download** (*Letöltés*) button in its top-right corner. The panel lets you choose:

- **Format:** Excel (one worksheet, numbers stored as numbers), CSV (semicolon-separated, so Hungarian Excel splits it into columns) or JSON (for machine processing).
- **Rows:** ‘All rows’ (*Minden sor*), ‘Filtered rows’ (*A szűrt sorok*) or ‘Selected rows’ (*A kijelölt sorok*). You can only select rows in tables that have a checkbox on each row (for example the tables in Result). By default the narrowest scope is chosen: the selection; failing that, the filter; otherwise all rows.
- **Columns:** only the visible columns, or all columns including the hidden ones.

Before you download, the panel shows the number of rows and columns; the row order matches the table. The file goes to your browser's downloads. Text that looks like a formula does not turn into a formula in the file.

## 4. Starting work

**The case list** (*Ügyek*, 263): a row for each main case - its process, its own party (*Gazdálkodó*), its period
(*Időszak*), its steps as small marks (done, in progress, not started, failed; each named when you point at it), the
step it is at and what that waits for. A sub-case is its main case's step, not a row of its own: the row names its step
(for example ‘Incoming invoices › Processing’), and the step a person must act on comes first. The views stand in the left
panel with their counts: **Cases waiting for me** (*Rám váró ügyek*: an open case waiting for a person's start, decision
or a failed step's retry, yours or no one's), **My cases** (*Saját ügyeim*), **Every open case** (*Minden nyitott ügy*),
**Closed cases** (*Lezárt ügyek*), and **By process** (*Folyamatonként*). The list is grouped by process at first
(**Group by**, *Csoport*, changes it) and keeps its search, filters and sorting when you come back. A process repeated by
period (the monthly reconciliation) also shows its **Period grid** (*Időszak-tábla*): a row for each party, a column for
each month, the case's state in the cell, linked to it.

Work starts as a case: **Cases › New case** (*Ügyek › Új ügy*, section 4.2) lists the processes a person may start, and each process's form asks what its case needs. The new work wizard (*Új munka*) is gone since 2026-10-28: its single kinds are processes of their own, and its workflows are multi-step processes (section 4.1). What the forms of the most used processes ask:

- **Documents** (*Iratok*): each document's type is recognised and its data extracted. Three sources:
  - **Documents from a folder** (*Egy mappa dokumentumai*): fill in ‘The folder's full path’ (*A mappa teljes útvonala*), or click **Browse…** (*Tallózás…*) and choose the folder in the Windows folder picker. The batch gets the supported documents directly in the folder, in path order: PDF, DOCX, XLSX, UTF-8 TXT and CSV. Tick **Its subfolders too** (*Az almappái is*, off by default) to include supported documents in subfolders too. The output folder of the named copies (section 10.2) is left out, so earlier copies do not return as new documents. A document in a subfolder is shown with its relative path (for example `2026-09/invoice.pdf`). ‘Name’ is optional; if empty, the process's title and the folder name are used.
  - **Chosen files** (*Megadott fájlok*): in ‘The files' full paths, one a line’ (*A fájlok teljes útvonala, soronként egy*) you can list files from several folders. **Browse…** opens the Windows file picker, where you can choose several files at once. The chosen files are added after the lines already in the field, each only once.
  - **Example documents** (*Példairatok*): a packet of the process's invented documents (section 4.2).

  **Browse…** asks the local service to open the Windows picker on this computer. While the picker is open, the button reads ‘The picker is open…’ (*A választó ablak nyitva…*). If you cannot see the picker, check the taskbar: it may have opened behind the browser. Cancelling changes nothing. A path can always be typed instead. Only one picker can be open at a time, and one left open for ten minutes is closed.
- **Emails from a mailbox** (*Levelek postafiókból*): the mailbox download's fields (the mailbox, its folders, the days the emails were received, at most how many; section 10.1). The worker downloads the new emails into the case's batch.
- **Bank statements** (*Bankkivonatok*): one own party's bank statements for a period (section 5.4). Choose the own party, the period and a folder or chosen files (or the example statements); the case's step takes into its batch the statements of the party and the period that the store has not got yet.
  - **What code reads** (free, without any AI service): an Excel or CSV export (for example a Revolut statement) gives one statement per account; a folder of Erste XML exports gives one per month. The Erste export has no balances and does not name the merchant of a card payment, so the month's PDF statement completes it when it stands next to the export or in a `pdf` subfolder with the same date and account in its name (`20260630_<account>_excel.xml` and `20260630_<account>_S.pdf`): the balances, the merchant and, for a purchase in another currency, the original amount (for example 20.00 USD). A CIB bank statement (a current account or an investment client account) is read by code too, from the PDF itself or from the bank's text export (`.txt`): its balances, and each line's counterparty, account and memo; such a PDF is not offered for extraction. The CIB credit card statement is read by code too: each purchase with its merchant and, in another currency, its original amount; its balances are checked by the closing balance, as it prints no running balance. A bank's standard XML statement (ISO 20022 camt.053, for example Erste's) is read by code with its balances, partners, card merchants and original amounts, so it needs no PDF; its line kinds are named as the bank's Excel export names them. A month without its PDF gets one to-do in the run; an account no party holds yet goes to the case's party when you approve the live run.
  - **Which bank files can the system read?** (*Milyen banki állományokat tud olvasni a rendszer?*, 146), in Settings › Processing: per kind of file its bank, the files, whether code reads it (free) or AI extracts it (paid), the facts of the statement and of each line it reads and does not read, its checks and notes, and the files no reader knows (for example another bank's PDF statement: recognised, then a to-do). The same list stands as a document in [bank files](../BANK_FILES.md). It is generated from the readers' own configuration, so it changes with them.
  - **PDF statements** (*PDF-kivonatok*): a PDF no export uses and no code reads is recognised by the run: a bank statement's data is extracted by AI within the run's budget (paid); any other document stops with a to-do (‘This PDF is not a bank statement…’), without extraction. A PDF the store has processed already is not ticked.
- **Reconciliation** (*Egyeztetés*, section 5.3): choose the own party (section 10.3) and the period; the case pairs the lines of the party's accounts and cards (those the store has statements of and those registered with the party) with the invoices already processed. A month without a statement only warns: its invoices show ‘No statement for its period’ (*Az időszakára nincs kivonat*), never ‘No payment found’. It processes no file and calls no AI service unless a person starts its AI proposal.

After **Create** (*Létrehozás*), the case's page opens, and the person who started it becomes its owner. The files stay where they are and are never changed. As a document is added, the system keeps an unchanging copy of it (its source instance), and from then on the batch works from that copy: processing, the page image in review and the named copies. So if the original file is later edited, moved or deleted, you still see exactly what the result was made from. Documents can be added to an existing batch later too (section 7.9), and a work folder starts a case for its new batch by itself (section 10.2).

### 4.1 Multi-step processes

A **multi-step process** (*többlépéses folyamat*; until 2026-10-28 a workflow, *munkafolyamat*) is one case whose steps each run a case of another process, a **sub-case** (*részügy*), and wait until it closes. Four can be started from New case: **Monthly reconciliation** (*Havi egyeztetés*: the incoming invoices and the bank statements side by side, then the reconciliation), **From the mailbox to the reconciliation** (*Postafiókból az egyeztetésig*: a mailbox's emails with their attachments in place of the invoices' folder), **Monthly reconciliation with invoices from a folder and a mailbox** (*Havi egyeztetés mappából és postafiókból érkező számlákkal*) and **From the mailbox to the batches** (*A postafiókból a kötegekbe*: a mailbox download, then the routing of its emails' documents).

- **Starting one:** the form asks the own party and the period once, then each step's own documents with the same fields as a one-step process (a folder, chosen files, the invented documents of the sub-case's process, or a mailbox download). **Create** can be pressed once every step has its documents.
- **Its page** (263: one case, one track): the case's **process track** (*folyamatsáv*) runs left to right at the top: the **Overview** (*Áttekintés*), then each step numbered, the next one ringed, and the **Log** (*Napló*: its events, cost and the settings it keeps) apart at the right end. The Overview shows what holds the case and the sub-work table: each step with its state (‘Not started yet’, *Még nem indult*; ‘Its case is in progress’, *A részügy folyamatban*; ‘Its case is done’, *A részügy kész*; ‘Did not finish’, *Nem futott le*) and its own next step. Choosing a step opens its work under it, on a second, quieter track: its batch's Processing, Review and Result, or its sub-case's parts. The page's main action at the right end of the title row is the case's next step when it is done on another part.
- **The sub-cases:** each is a case of its own process, named after its step (‘… · Incoming invoices’); since 263 it opens under its step on the main case's page and has no row of its own in the case list (the main case's row names its step). Its paid run waits for a person's start with its cost cap shown. Once a sub-case is done, the steps after it start by themselves; the reconciliation's sub-case takes the party, the period and the party's accounts.
- **A sub-case closed otherwise** (cancelled, or its batch deleted): its step stops with why, and **Try again** (*Újrapróbálás*) starts a new sub-case; the earlier one stays linked.
- **The cost:** the Log adds up what the sub-cases spent, step by step.
- **The workflows made before** are under Settings › Operations › **Earlier workflows** (*Korábbi munkafolyamatok*): each one's page shows its chain as it stood; no new one is made there and none is repeated, and an open one may still be archived. The old address of a new workflow opens New case.

### 4.2 New case

**New case** (*Új ügy*, 231 U0) on the **Cases** (*Ügyek*) page starts a case of any process a person may start by hand. **Which process?** (*Melyik folyamat?*) lists them, each with what it is for; one whose case cannot start yet says what it needs (‘Before a case can start: … needs an active version’, *Mielőtt ügy indulhat, élő változat kell ebből: …*: a product or a tariff no one has made active). Choosing a process opens its own form below: what a case of it needs (the documents, the own party and the period, the record it starts from, the batches it reads; a multi-step process each step's documents, section 4.1) and an optional name (without one, the case is named by its process and what it reads: a mailbox download by its addresses and period, such as ‘… · office@example.com · the last 7 days’); **Create** (*Létrehozás*) starts the case and opens its page.

**Example material** (*Példaanyag*): a process may come with invented data to try it on. Its card says what the material holds and whether it is installed. **Install the example material** (*A példaanyag telepítése*) puts it in: the system makes each thing and you make it active (so the second person a product needs is you); it is the page's main step while a case cannot start without it. Its packets of invented documents then appear among the form's sources as **Example documents** (*Példairatok*): choose a packet and **Create**; the documents are written beside the store (as PDFs, or a bank's XML statements) and the case starts on them. The bank statements and the reconciliation are tried on an invented own party (Minta Tanácsadó Kft.): installing their example material makes the party with its account; read its invoices in the documents process (their own packet) and its statements in the bank statements process first, then reconcile March to June 2026, as the card says. The mailbox download is tried on the consultancy's invented mailbox, iroda@minta-tanacsado.example (Inbox and Sent Items, 1 March to 31 October 2026): it is read without Outlook, and its download can then be routed. Their processing run is a live run like any other: its paid calls stay within the budget shown on its button. Nothing in the material is real, and the products, rules and tariffs it made say ‘example’ (*példa*) in Settings. **Remove the example material** (*A példaanyag eltávolítása*, it asks for confirmation) takes it out in one go while no case keeps any of it; while one does, it stays and the message names the cases.

## 5. The document batch page

The header shows the batch name and a summary (how many documents or emails, when the last run was). Next to it:

- **Assignee:** the batch's owner (the person from the Users list assigned to it), or ‘no owner’ (*nincs felelős*). This is not a permission; other people can work on the batch too. The **Only my document batches** filter is based on it.
- **The next-step button**, for example ‘Start trial run →’. If you are already on that stage's page, only the label ‘Next step: …’ (*Következő lépés: …*) is shown.
- **Manage batch** (*Köteg kezelése*) (section 5.1).

Below this are the tabs of the three stages, each showing its own state: **1 Processing** (for example ‘ready to start’ (*indítható*), ‘cannot start’ (*nem indítható*), or the last run's mode, state and progress), **2 Review** (‘To-dos: N’ (*N teendő*) or ‘no to-dos’ (*nincs teendő*)), **3 Result** (‘none yet’ (*még nincs*), ‘trial result’ (*próba-eredmény*), ‘awaiting approval’ (*jóváhagyásra vár*), ‘released’ (*kiadva*)). By default a batch opens at the stage where its next step is. You can bookmark the address in the browser's address bar: it takes you back to the same batch and stage.

The possible next steps are: ‘Empty document batch’ (*Üres köteg*), ‘Start trial run’, ‘Cannot start’ (*Nem indítható*), ‘Running: 3/10’ (*Fut: 3/10*), ‘Failed or stopped run: rerun’ (*Hibás vagy leállított futás: újrafuttatás*), ‘N new item(s) to process’ (*N új tétel vár feldolgozásra*: documents added after the last run that no run of its kind has processed yet), ‘Review: N to-dos’, ‘Trial OK: live run’ (*Próba rendben: éles futás*), ‘Trial finished: live run (N to-dos in the trial)’ (*Próba kész: éles futás (N teendő a próbában)*), ‘Approval’ and ‘Released: download result’ (*Kiadva: eredmény letöltése*). ‘Review: N to-dos’ follows a live run only: a trial run cannot be approved, so after a trial with to-dos the next step is the live run, and the trial's to-dos are shown only as information (you can still look at them on the Review stage, which opens the latest run).

### 5.1 Manage batch

- **Rename** (*Átnevezés*): enter a new name, then click **Save**.
- **Hide from the list** (*Elrejtés a listából*) / **Show in the list again** (*Visszahozás a listába*): a hidden batch keeps its runs and results, can still be opened directly, and reappears in the list when you tick **Hidden batches too**. A watched folder does not add new documents to a hidden batch; it starts a new batch instead.
- **Delete permanently…** (*Végleges törlés…*): only possible on a batch that has never had a run. It asks for confirmation (‘Delete this batch permanently?’ (*Biztosan törlöd a köteget?*)). The batch and its item list are deleted; the files stay where they are. Deletion cannot be undone, and a record of it stays in the log. A batch that has runs can only be hidden.

### 5.2 Original or unified names

The batch's documents, the items of a run and the item list of Review can show each document under its original file name or under its **unified name** (*egységes név*): the content-based file name of the File names view (section 8), for example `2026-09-12_SZAMLA_Minta-Kft_SZ-2026-001234.pdf`. The **Name:** (*Név:*) switch above each of these lists chooses between **Original** (*Eredeti*) and **Unified** (*Egységes*). The choice applies to every list and is remembered for the person in **Who is working?** in this browser; the default is Unified.

- A document has a unified name only once a run has processed it. Until then its original name is shown, and its tooltip says ‘No unified name yet: the item has not been processed.’ (*Még nincs egységes név: a tétel még nem futott le.*). In the batch's list, each document's name comes from the latest run that processed it.
- A ⚠ mark before a unified name means the name is uncertain: its copy would go into the review folder. Pointing at the mark shows why (for example a missing invoice number). Correcting that field in Review makes the name certain.
- With a unified name shown, the tooltip gives the original name. Searching, sorting and filtering work on the name that is shown; the search also finds the other name.
- Emails have no file name of their own and always keep their subject.
- The **Columns** menu offers **Unified name** (*Egységes név*), **Original name** (*Eredeti név*) and **Unified name status** (*Egységes név állapota*: ‘Done’, ‘To check’ (*Ellenőrzendő*), ‘Not yet’ (*Még nincs*), ‘None (email)’ (*Nincs (levél)*)), so both names can be seen side by side.

### 5.3 A reconciliation batch

A reconciliation batch (*egyeztetési köteg*) pairs the lines of your bank and card statements with invoices already processed in other batches: an outgoing payment with an incoming invoice, and (148) incoming money with an outgoing invoice the batch's party issued, whose partner is the buyer. Incoming money with no outgoing invoice to pair stays informational, as before. It has no files and no runs; it works on the corrected values of the documents. Every decision belongs to the pair of a line and an invoice, not to the batch: another batch with the same line shows the same decision. A batch is one own party's (section 10.3): it lists that party's invoices and the invoices no party claims; a batch made before the own parties takes every invoice as its own. Its stages are different:

- **1 Preparation** (*Előkészítés*):
  - **Scope** (*Kör*): the own party (*Saját gazdálkodó*), the accounts and cards and the period; **Save the scope** (*Kör mentése*) keeps every decision made so far. A batch made before the own parties can be given its party here.
  - **Coverage** (*Lefedettség*): per account and month, how many statements there are; ‘✓ 2’ means two statements whose balances check out, ‘! 0/1’ a statement whose balances do not, ‘–’ no statement. **Recompute** (*Újraszámolás*) fetches the missing MNB exchange rates (only dates and currency codes leave the computer).
  - **The batch's items** (*A köteg tételei*, 169): what the pairing takes, as in every batch (section 7.9). The first line counts the documents: statements (*kivonat*), invoices (*számla*), the invoices of other parties when the batch has an own party, and the left-out ones (*kihagyva*, a dash). Each row is a statement of the scope or an invoice the pairing may take, with its kind, its number or account, partner, date or period, amount, **Batch** (*Köteg*: where it was processed, a link), **Counted run** (*Érvényes futás*: approved, processed live, processed in a trial, accepted as a source or an evaluation on the command line, a link to the run) and **In the pairing** (*A párosításban*: an invoice's state); the column menu adds **Open lines** (*Nyitott sorok*: a statement's lines still to decide), **Blocks the approval** (*Akadályozza a jóváhagyást*) and the currency. **Other parties' invoices too** (*Más gazdálkodók számlái is*) shows the invoices of other own parties. **Open document** and **Download** open the file from its own batch.
    - **Leave out** (*Kihagyás*), or for several ticked rows **Leave N out of this reconciliation…** (*N tétel kihagyása ebből az egyeztetésből…*), asks why (*Miért hagyod ki…?*); the reason is required and recorded with your name in the batch's log. The document stays in its own batch and in every other reconciliation: only this batch no longer takes it. A left-out statement's lines leave the batch (and its coverage), a left-out invoice is not proposed or paired here. A document a pairing or a ‘needs no invoice’ mark of this batch rests on cannot be left out until you revoke that, and an approved batch takes no change until its approval is reopened. **Left-out documents too** (*Kihagyott iratok is*, with their count) shows them with who left them out, when and why; **Restore** (*Visszaállítás*) takes one back.
    - **Add documents** (*Iratok hozzáadása*): files are added to an existing batch, as a reconciliation batch has none of its own. Choose **Invoices** (*Számlák*) or **Bank statements** (*Bankkivonatok*) and the batch they go to (the documents batches already giving this reconciliation documents come first; the statement batches are the own party's), then follow that batch's three steps (section 7.9). The files wait for processing there: **Process them there** (*Feldolgozás ott*) opens that batch's Processing, where the run's button shows its cost cap. Once processed, they take part in the reconciliation by themselves.
  - **Decisions not carried over** (*Át nem vitt döntések*, only when there are any): a better statement replaced a statement of the scope, and a decision made on one of its lines (a pair, ‘needs no invoice’) has no same line on the valid statement. **Revoke** (*Visszavonás*) each, then make it again on the valid statement's lines.
  - **Decisions that no longer count** (*Már nem érvényes döntések*, only when there are any): pairings and ‘needs no invoice’ marks that count nowhere, each with its reason: an amount of the line or the invoice changed since, the invoice no longer takes part in the pairing (for example its amount was corrected to zero or a second copy of it arrived), or the line was changed or read again, so it is no longer on its statement as it was. **Revoke** (*Visszavonás*) each, then decide on the line again.
  - **What blocks the approval** (*Mi akadályozza a jóváhagyást*): source documents whose run is not approved, or that were processed on the command line (until you accept them in the Result stage), decisions not carried over and decisions that no longer count. Pairing can start anyway. **Warnings** (*Figyelmeztetések*): statements whose balances do not check out; they do not block the approval (145).
  - **Where the pairing stands** (*Hol tart a párosítás*): the lines and invoices by state.
- **2 Pairing** (*Párosítás*) opens on **the quick review** (*Gyors áttekintés*, 147); **Cards** (*Kártyák*) switches to the cards. Below them, **The batch's items: add, open, leave out** (*A köteg tételei: felvétel, megnyitás, kihagyás*) opens the same item list as in Preparation.
  The quick review shows the lines you still decide in groups, by what is known of them; each line is in the first group
  that fits:
  - **Sure pairs** (*Biztos párok*): the invoice number or another sign and the exact amount tie the line to one invoice,
    on a statement whose balances check out (the same as the cards' accept button).
  - **As decided before** (*Korábbi döntés szerint*): the reason you gave the partner's other lines.
  - **By the bank's category** (*A bank kategóriája szerint*): an ATM withdrawal is cash, an exchange or a top-up a transfer
    between own accounts.
  - **Salary** (*Bér*): the memo or the description says salary (for example *munkabér*).
  - **Sure by AI** (*AI-val biztos*): both AIs (JEV and GPT) read the same kind of payment, it means a ‘needs no invoice’
    reason, and JEV is at least 0.95 sure of it (the policy's threshold). The two models agree; that is not a checked fact.
  - **AI suggestion: look at it** (*AI-javaslat: nézd át*): only one AI answered, or JEV is less sure: its lines start
    unticked.
  - **An invoice is expected** (*Számla várható*) and **To decide on the cards** (*A kártyákon eldöntendő*): for information;
    **To the cards** (*A kártyákhoz*) opens the cards.

  Each group shows its count and total, a line of how it is known and its lines (date, amount, partner, memo and the
  suggestion: the reason, the invoice, the AIs' kinds with their probability). A line with a candidate invoice is never in
  a reason group. Untick the lines you do not agree with, then **Accept N line(s)** (*N tétel elfogadása*, it asks for
  confirmation): the sure pairs are paired, the others marked as needing no invoice with the group's reason, and the mark
  records which suggestion it came from. If the group changed meanwhile, nothing is saved and the review is reloaded.
  **Left out by the code** (*A kód által kihagyott tételek*) counts the lines the code leaves out, by reason.
- **The cards** (*kártyák*, 142). A card holds what belongs together: a transfer with
  the invoices it pays, an invoice with the transfers that paid it (in parts, or more than once), or a transfer or an
  invoice standing alone.
  - **Every fact of both sides:** for a transfer its booking and value day, amount (and original amount), counterparty and
    their account, memo, description, the balance after it, the account and the statement; for an invoice its supplier, tax
    number, number, issue, fulfilment and due date, net, VAT and total, payment method, the supplier's account, references,
    buyer and file.
  - **The pairs** below them: each transfer–invoice pair with its amount, its state (paired, proposed, may repeat the
    payment) and **against the due date** (*a határidőhöz képest*): ‘5 days late’, ‘on the due date’, ‘3 days before the
    due date’ or ‘no due date’. Every day after the due date counts as a delay. Under each invoice: when it was paid (or
    the proposed payment) and how late, or ‘Overdue, no payment found: N days after the due date, by <day>’, the last day
    the batch's statements cover it without a gap.
  - **The totals** of the transfers and the invoices, in words: they match, more was transferred than invoiced, or part
    of the invoices is not paid by these transfers.
  - **The lists** (chips at the top, each with its count): ‘To decide’ (*Eldöntendő*, the default), ‘Transfers without an
    invoice’, ‘Invoices without a payment’, ‘Overdue, no payment found’, ‘Paid late’, ‘Possible double payment’, ‘To
    clarify’, ‘Paired’, ‘Needs no invoice’, ‘Cancelled by a credit note’, ‘Left out’ and ‘All’. A **possible double
    payment** is an invoice two or more transfers each look like the full payment of (paired or proposed for it, or of
    its exact amount, tied to it by its number, the supplier's account or name, in its period, paying no other invoice):
    it may be paid twice, or the invoice of another month is missing. A transfer you marked as needing no invoice, or
    rejected for the invoice, does not count. The overdue list never says ‘unpaid’: the statements show nothing about cash
    or another account.
  - **Actions** on a card: **Accept** (*Elfogadás*, Enter) pairs the card's proposal at once; **Accept this one**
    (*Ezt fogadom el*) when a transfer has several candidates; **Not this one** (*Nem ez*) with a reason; **Undo**
    (*Visszavonás*) a pair; **Needs no invoice** (*Nem kell számla*) with a reason; **Pair by hand** (*Kézi párosítás*)
    opens the two lists with the card's transfer selected.
  - **Documents** (*Iratok*, key `d`): the statement page with the transfer framed and the invoice beside it; when a card
    has several, chips choose which. A card that asks for a look (several candidates, a different amount, a possible
    double payment, an amount left, a statement whose balances do not check out) opens them by itself when selected.
    The statement pane is described under the two lists' **Documents** below (144). A card shows every fact of the
    transfer; the statement's file name stands only in the documents.
  - Keys: ↑ ↓ or `j` `k` move between the cards, Enter accepts, `d` shows the documents.
- **Two lists (pair by hand)** (*Két lista (kézi párosítás)*): the earlier page, for searching an invoice by hand and for
  selecting many lines at once; **Back to the cards** (*Vissza a kártyákhoz*) returns.
- **The two lists** side by side:
  - **Statement lines** (*Banki tételek*) on the left, filtered by state: ‘To decide’ (*Eldöntendő*, the default), ‘Proposed pair’, ‘Same amount only’, ‘Partly paired’, ‘No candidate’, ‘Paired’, ‘Needs no invoice’, ‘Left out’ (an incoming payment, a fee or interest, a transfer between own accounts; with the reason) and ‘All’; by account, month and a search in the name, memo and amount. Clicking a line selects it; the checkbox (or Ctrl-click) adds more lines to the selection; ‘Select all shown’ (*A látható tételek kijelölése*) selects the whole filtered list.
  - **Invoice expected** (*Számla várható*): the lines still to decide, without a candidate, whose kind of payment (as JEV or GPT read it) expects an invoice: a utility or telecom bill, a subscription, insurance, an online order. Their invoice is probably missing from the store; choosing this filter also groups the lines by partner, so the list says which invoices to look for.
  - **By partner** (*Partnerenként*): groups the lines by partner, the name on the line without its reference numbers. A group's head shows its lines and their total, the AI's kinds of payment, how many invoices are expected and the suggested reason; its checkbox selects the group's lines, **Needs no invoice (N)** (*Nem kell számla (N)*) opens the reason for the group's lines still to decide, and **Undo the marks (N)** (*Jelölések visszavonása (N)*) undoes the group's marks in one step.
  - **Filters** (*Szűrők*) under each list's head: the lines by partner, the AI's kind of payment, direction and amount (from–to); the other invoices by supplier, own party, currency, state, issue date (from–until), amount, nearness to the selected line's amount (within the given percentage, in its currency) and having a candidate (*Van jelöltje*). The button shows how many filters are set; **Clear the filters** (*Szűrők törlése*) removes them. A supplier or party filter also finds another party's invoices, as a search does. The selected line's candidates are never filtered out.
  - **The suggested reason** (*javaslat*) for lines that need no invoice is the reason given earlier for the partner's other lines, in any batch (a line through a payment app such as iCsekk teaches nothing); otherwise (140) the one the lines' own category in the bank's export suggests when every line has it, ‘The bank's category suggests: …’ (*A bank kategóriája alapján: …*): a Revolut exchange between your currency accounts or a top-up is a transfer between own accounts, a cash withdrawal (ATM) is cash; otherwise the one the AI's kind of payment suggests when JEV and GPT agree on every line, or when only one of them answered. It is only chosen in advance in the reason panel: nothing is saved until you save it.
  - **Invoices of the party** (*… számlái*) on the right: the **finder** (*párkereső*, 143), which compares the selected line
    with every invoice of the page in code (free) and says which ones fit and why.
    - **At the top, pinned** (*Ehhez keresünk számlát*): the selected line with its date, amount and partner, then every
      fact of the transfer in labelled fields (144): booking day, value day, original amount, partner, the partner's
      account, memo, description, balance after and the own account or card; the statement's file name stands only in
      the documents. Then a bar of how much of it the ticked invoices cover: ‘Still to cover: …’ (*Még
      lefedetlen: …*), ‘Covered exactly’ (*Pontosan lefedve*) or ‘More than the line: …’ (*Több, mint a tétel: …*). Below it
      what was decided on the line, each with **Undo** (*Visszavonás*); the AI's kind of payment per engine with its
      probability (‘asked once for the partner’, *a partnerre egyszer kérdezve*, when it was asked on another line of the
      partner and taken over without a call); the reasons given earlier for this partner.
    - **Invoices that fit** (*Illő számlák*), numbered for the keys 1–9: the code's proposal first (‘proposed by code’, *a kód
      javaslata*), then, the strongest first, the line's other candidates, an invoice whose number or reference number the
      memo names (even outside its dates: an advance or a late payment), one tied by the supplier's account, name or a learnt
      name within its dates, and one of exactly the same amount within its dates. An invoice the AI chose stands here too,
      with the engines that chose it (‘JEV 0.87’; ‘AI only’, *csak AI*, when nothing else ties them). When none fits, the
      page says so and offers **Needs no invoice** (*Nem kell számla*) with the suggested reason.
    - **By amount only, nearest first** (*Csak az összeg alapján, a legközelebbi elöl*): the other free invoices, those of the
      line's currency first; 30 at first, more on request.
    - **Bound to another line or settled (N)** (*Másik tételhez kötött vagy rendezett számlák (N)*), closed until opened: an
      invoice paid (by another line, or by this one), cancelled by a credit note, proposed for another line (with that
      line's date and amount), or rejected for this line.
    - **Every row** shows the invoice (supplier, number, issue and due date), its amount (what is left of a partly paid one)
      and how it differs from the line: ‘exact amount’ (*pontos összeg*), ‘less than the line: …’, ‘more than the line: …’,
      or the converted amount at the MNB rate. Three columns say what matches: **Name** (*Név*), **Number** (*Szám*: the
      memo names the invoice or a reference number) and **Bank account** (*Bankszámla*: paid to the account on the invoice):
      ✓ matches, ≈ similar, ✗ does not match, a red ✗ paid to another account than the one on the invoice, – nothing to
      compare; pointing at a mark says it in words. **Against the due date** (*A határidőhöz képest*): the days before or
      after the due date (every day after it is a delay), ‘outside the invoice's search period’ when it fits only by its
      number, and why an invoice is not free.
    - Until the comparison arrives, or when the service cannot give it, the code's candidates still stand first and the rest
      by the nearest amount.
    - An invoice no party claims is marked ‘no own party’ (*nincs gazdálkodója*). Another party's invoices show with the
      ‘Other parties' invoices too’ (*Más gazdálkodók számlái is*) switch, or when a search finds them, marked ‘Other
      party: …’ (*Más gazdálkodó: …*); when the selected line's candidate is another party's invoice, a note says so, with
      **Show them** (*Mutasd őket*). Such a pair is never proposed and never accepted in bulk: a person pairs it on purpose
      (for example a company invoice paid from a private card). Without a selected line the invoices are listed newest
      first.
  - **The selection bar** at the bottom shows the selected lines and invoices with their totals and the difference, and acts on them:
    - **Pair** (*Párosítás*): one line with one or more invoices, or one invoice with one or more lines (instalments). When the amounts settle every side, it is saved at once. When a rest is left, the amounts can be set per pair and a reason is required (for example an instalment, a bank fee, a discount). A card line in forints and an invoice in another currency pair only one to one, in whole; outside the card band or without an exchange rate it needs a reason.
    - **Not this one** (*Nem ez*): rejects the selected candidate with a reason; it is never offered again (until undone).
    - **Needs no invoice** (*Nem kell számla*): marks all the selected lines at once, with one reason (private expense, bank fee or interest, transfer between own accounts, tax or contribution, cash withdrawal, salary, or other with a note).
    - **Accept the N unambiguous proposals** (*Egyértelmű javaslatok elfogadása (N)*, it asks for confirmation) pairs every proposal that is the only candidate of its line and its invoice, on a statement whose balances check out, with an invoice of the batch's party or of none.
  - **Documents** (*Iratok*, key `d`): the statement opens at the page of the selected line, with the line framed (found by its amount and date), next to the selected invoice (or the first candidate). A document processed on the command line has no image here. **Open in its batch** opens the document's review page in a new tab.
    - **The statement pane** (144) starts with the line's facts as the statement prints them (*A tétel a kivonaton*). A
      statement read by code (a CIB PDF's text, a bank's table or XML export) is stored as the reader's own statement
      file, which has no page: the pane shows the bank's PDF it was read from instead, found again in the folder of the
      batch that brought the statement (or wherever the store saw the same file), only while its content is the one
      that was read; its name stands in the pane's head. The pane says when a table or XML export has no PDF, and names
      a PDF moved away or changed since: put it back in the folder to see it again.
    - **Facts beyond the money** (144): a statement read by code also shows what the bank printed about the line: the card
      (only its first six and last four digits), when the purchase was made, the terminal and the authorisation code,
      the exchange rate, the fee, the bank's reference, the order id and the parties' end-to-end id; only the ones
      the statement prints. They stand in the line's facts on the cards, in the finder and in the documents.
    - **The statement as read** (*A beolvasott kivonat (N tétel)*): the statement's heading (bank, account, period,
      opening and closing balance, whether the balances check out) and its lines around the selected one, highlighted;
      **All N lines** (*Minden tétel (N)*) shows every line. It is open when there is no page to show, folded otherwise.
  - The selected line on the left list shows its whole memo (144); the others stay on one line.
  - After a decision the next line is selected. If someone else decided meanwhile, the lists are reloaded and your selection is kept.
- **3 Result** (*Eredmény*, 145): the reconciliation's summary, its download and its approval.
  - **The summary:** every invoice of the batch with its result: **Paid** (*Kifizetve*), **Partly paid** (*Részben
    kifizetve*), **Settled by a credit note** (*Sztornó számla rendezi*), **Proposal to decide** (*Eldöntetlen javaslat*: a
    proposal is no decision), **No payment in the covered period** (*Nincs fizetés a lefedett időszakban*: verified statements
    cover its payment window and show no payment) and **Statements do not cover it** (*A kivonatok nem fedik le*); with the day
    it was paid and the days late or overdue. Another party's invoice is listed only when a line of the batch paid it, with
    its party. Every statement line with its result: **Paired** (*Párosítva*), **Partly paired**, **Needs no invoice** with
    your reason, **Left out** with the code's reason (incoming money, a fee …) and **Open** (*Nyitott*).
  - **Warnings** (*Figyelmeztetések*): a statement whose balances do not check out, a month of an account without a
    statement. They are listed, they do not block.
  - **Download** (*Letöltés*): an Excel workbook with two sheets, **Számlák** (invoices) and **Tételek** (statement lines),
    each under a heading naming the batch, the party, the period, the accounts and the state (‘Tervezet — nem jóváhagyott’
    before the approval, the version and who approved it after). Money is written as numbers, the header row is filtered and
    stays in place when scrolling.
  - **What blocks the approval:** a source document whose run is not approved (approve that run first), or a decision not
    carried over. An invoice counts when a line of this batch paid it; the batch party's own invoice also when it
    has a candidate here or was paid elsewhere. An invoice of no own party, or another party's invoice paid in another
    batch, does not block. A document processed on the command line belongs to no run: **Accept N command-line documents as
    sources** (*N parancssori irat elfogadása forrásnak*) records your name and the time; when the document is processed
    again, its new result has to be accepted again. Open lines do not block the approval: the summary lists them.
  - **Approve the reconciliation** (*Az egyeztetés jóváhagyása*; it asks for confirmation): records the summary you see as an
    unchangeable **version** (*változat*). If anything changed since the page was shown, nothing is recorded and the page
    reloads. From then on the decisions on its lines are **locked** (*zárolva*) in every batch, the batch's scope cannot
    change, and the Preparation and Pairing stages are read only.
  - **Reopen** (*Újranyitás*, with a reason): the lock goes; the version stays among the **Earlier versions** (*Korábbi
    változatok*), each still downloadable as it was approved, and the next approval makes a new version. If the data changed
    after an approval (for example a document was processed again), the page says so; the approved version stays as it was.
    When only the reconciliation's rules (or the program that applies them) changed and its invoices, lines and results
    are the same, the page only notes it: the approved version holds.

**How the code finds a candidate** (free, no AI service): a line and an invoice of the same currency are a candidate when the
line falls within the invoice's dates and at least one more detail ties them: the invoice number or a reference number in the
memo, the supplier's account number, or the supplier's name (also glued to other text or one letter off). The amount alone is
never enough: a line with exactly an invoice's amount but nothing else tying them is only listed (‘Same amount only’) for you to
decide from the documents. The system never calls an invoice unpaid; it only says when no payment was found in a period the
loaded statements cover.

- **Card payments in another currency:** a card line in forints and an invoice in dollars or euros are compared through the
  official MNB exchange rate of the invoice's issue date; the line must be booked between 3 days before and 10 days after the
  issue date, and its amount between 2% below and 5% above the converted amount. Only dates and currency codes leave the
  computer when the rates are fetched.
- **Bank transfers in forints for an invoice in another currency:** a forint line of a bank account and an invoice in
  francs, dollars or euros are compared at the MNB exchange rate of the invoice's fulfilment day (a Hungarian customer pays
  the forint value the invoice states), then of the day the bank booked the line (the bank converted the money); the line
  is looked for in the invoice's payment window. The candidate says which day's rate the amount matched at (*a teljesítés
  napi* / *a könyvelés napi MNB-árfolyamon*). Outside the band the pair is listed only when the line's memo names the
  invoice. Run **Recompute** (*Újraszámolás*) once so that the missing rates are fetched.
- **Payment method:** a bill payable by postal cheque (*csekk*) paid through a cheque payment app (PostaCsekk, iCsekk) shows
  the app's name, not the supplier's; with the cheque as payment method and exactly the same amount the pair is proposed.
- **A card purchase's original amount:** when the bank prints a card purchase's original amount next to the forint line (the
  Erste PDF statement, for example 20.00 USD), the line is compared with an invoice of that currency on that amount, exactly,
  without an exchange rate; the line shows ‘originally 20.00 USD’ and the candidate says it was compared on it.
- **Names learnt from your decisions:** after you pair a line with an invoice, the line's name (without its reference numbers)
  ties later lines of that name to the same supplier. A line through a payment app teaches nothing.
- **One transfer for several invoices:** when a line's memo names several invoices and their amounts add up to the line's
  amount exactly, they are proposed together (‘with the other named invoices, the line's amount’). Choosing one of them
  chooses the whole group, and accepting the unambiguous proposals pairs them all. A forint transfer naming several invoices
  of one other currency (for example two franc invoices) is compared with their sum at the MNB rate, as a single invoice
  is (the fulfilment day's rate, then the booking day's); within the band they are proposed together (‘the named invoices
  together: …’). Paired, each invoice is settled in whole and the line's forints are shared in the ratio of the invoices'
  converted amounts.
- **Credit notes:** a supplier's credit note (a negative invoice) that cancels exactly one of its invoices settles it: the
  invoice shows ‘Cancelled by a credit note’ with the credit note's number, and no payment is looked for. Not when a line
  naming the invoice pays it (a refund may follow) or when two invoices could be meant. An invoice already paid counts
  among the ones it could mean: a credit note refunding a paid month does not cancel next month's unpaid invoice of the
  same amount; you decide.
- **Recurring bills:** a line booked more than 20 days before an invoice was issued is offered for it only when its memo
  names the invoice (an advance payment); otherwise it paid an earlier month. When a line's memo names one invoice, other
  invoices of the same amount are still listed under it, but not proposed.
- **Possible double payments and overdue invoices** (142): found by code as described under the cards above; they are
  facts to check, not decisions.

### 5.4 A statement batch

A statement batch (*kivonatköteg*, 140) is processed, reviewed and approved like any batch; its header says ‘Bank statements of <party>, <from> – <to>’. In its **Result** stage, above the usual views, **<party>'s statements** (*<party> kivonatai*) lists each item with its account, period and checks, and its state: ‘valid’ (*érvényes*), ‘replaced by a better statement’ (*egy jobb kivonat leváltotta*), ‘books the same days as another statement’ (choose the valid one on the review page) or ‘no statement from it yet’ (not processed yet, or not a bank statement). Below it, the party's months in the batch's period fold open (section 10.3), so what the batch changes shows before and after its run.

When you approve a live run, an account no party holds yet (or one dismissed as no own party's) goes to the batch's party, and the batch's log records it with your name; neither a trial run nor an unapproved live run assigns anything. Only such a registered account counts as an own account in a reconciliation: a payment to an account that a stored statement prints but no party holds (for example one read from an email attachment) stays among the lines to decide, marked ‘to an account not registered as own’ (*nem nyilvántartott saját számlára*); register the account in Settings › Own parties if it is yours. An account of another party stays where it is, and its statement gets a to-do: move the account in Settings › Own parties if it is this batch's party's.

### 5.5 An insurance quote (a case)

An insurance quote (*Biztosítási ajánlat*, stage D) is a case of the `insurance_offer` process: a folder of a business's documents (the quote request form, a property schedule per site, a claims history statement) becomes an offer a person accepts, a Word document and its covering letter. For now the product, its rules and tariff, the company register and the sanctions list are invented (Settings › **Products**, with its **Tariffs** list). Start it from **Cases › New case** (*Ügyek › Új ügy*, section 4.2): while no product and tariff are active, **Install the example material** (*A példaanyag telepítése*) puts the invented ones in, and the form's **Example documents** (*Példairatok*) starts a case on a packet of invented documents (a folder or chosen files work too). The company register and the sanctions list answer from the invented local service that `scripts\dev.ps1 start` starts beside the service. Its page has five views; the first view's first card says **What holds the case** (*Mi tartja fel az ügyet*): each step that waits for a person or did not finish, with the view where it is resolved as a link.

- **Overview** (*Áttekintés*): what holds the case, the documents' processing batch (start its live run there; the run reads each document's values, and its paid calls stay within the budget shown on the button), and what the case spent.
- **Data check** (*Adatok ellenőrzése*): the facts the documents give (*Tények az iratokból*: each with the document, page and words it came from), the company register's and the sanctions list's answers, and the field check. **What the sources disagree on** (*Amiben a források eltérnek*) comes first: the system never chooses between two sources, **Take this value** (*Ezt veszem át*) takes the other one. Then the units (the policyholder, its sites, their asset groups) and their facts, each correctable. Give the day cover starts and **Freeze the facts** (*A tények rögzítése*): the rules and the premium are computed from that frozen version; **Reopen the check** (*Az ellenőrzés újranyitása*) asks for a reason and makes a new one.
- **Calculation and versions** (*Számítás és változatok*): the rules' evaluation (its verdict, each unit's outcomes and the rule, document and clause that gave them), the missing facts with their deadline (enter them in the field check and freeze again; **The facts will not come** (*A tények nem fognak megérkezni*) closes the case with your reason), and the premium itemised line by line, with each version.
- **Decision and release** (*Döntés és kiadás*): first the **Risk decision** (*Kockázati döntés*): **Accept the risk** (*A kockázat elfogadása*) only when the rules allow it or refer it to a person; **Decline the risk** needs a reason and closes the case. Then the **Premium decision** (*Díjdöntés*): above the limit (for now an invented 300 000 HUF) another person than the risk decision's maker decides, and the page says who may not. Then the **Offer document** (*Ajánlati dokumentum*): the Word offer printed from the accepted premium (the policyholder, the product, the day cover starts, each cover's premium, the factors on the total and the annual premium), stored with its version and fingerprint; its link downloads that very file. Then the **Covering letter** (*Kísérőlevél*): written from its frame with the offer's values and addressed to the contact the request form names; change the address, the subject or the text if needed and **Accept the letter** (*A levél elfogadása*). A marker left in it or an address that is none keeps it from being accepted. Last, **Send** (*Elküldés*) puts the accepted letter, with the offer attached, into the output folder as an email file Outlook opens as a message to send; then the case closes.
- **History** (*Előzmények*): who did what and when, and the versions the case keeps from its start (the product, the tariff, the rule files).

A decision, the offer and the letter are approved versions: one made on a page that shows an older result is refused (reload and decide again), and when a step they build on gets a new result (the facts are frozen again, say), they go out of date and wait for a person again.

An **Insurance renewal** (*Biztosítás megújítása*) case works the same way with fewer steps: an existing client is asked only from the sanctions list, there is no wait for missing facts, and the **Renewal decision** (*Megújítási döntés*) offers **Renew** (*Megújítás*) only when the rules allow the risk; otherwise **Send to the full quote** (*Teljes ajánlatba küldés*) closes it with your reason, and the client gets a full insurance quote instead. Above a lower limit (for now an invented 100 000 HUF) another person decides the premium, and the covering letter has the renewal's own text.

## 6. Processing

### 6.1 Processing settings

The batch's processing recipe determines which documents it accepts. Choose **PDF and email processing** for PDF documents and downloaded emails. For DOCX, XLSX, UTF-8 TXT or CSV files, choose **Document processing — PDF, Word, Excel, TXT, CSV** and save the settings; this recipe also accepts PDFs in the same batch.

Settings › Processing shows each recipe's own title, supported inputs and explanation. **Recipe version: 1** identifies the revision of that particular recipe; two recipes can have the same version number. The path descriptions also follow the selected recipe in the batch settings. Word, Excel, TXT and CSV need GPT extraction, optionally checked by JEV; they cannot use the S path. Azure recognition applies only to PDF files. **Unknown PDFs** (*Ismeretlen PDF-ek*): when a PDF's recognised type has no fitting type pack (for example a declaration or a payment reminder), the default setting, general facts, still extracts source-bound facts with GPT and JEV, within the run's budget, and the document is reviewed like a Word or Excel file; the recognised type and its uncertainty to-do stay. With the other setting, a stop for manual review, such a PDF stops with a to-do, as before. A scanned PDF is read with local text recognition for this and always keeps a to-do saying that its reading is partial. The historical PDF path comparison does not measure extraction quality for the other formats.

Native documents use GPT to extract facts, with optional JEV support checking. The JEV-only S path is unavailable for these documents; an incompatible choice prevents the run from starting. Azure recognition applies to PDF files only. Reading gaps remain visible after review; checking an extracted value does not recover unread content.

- **A PDF document** (*PDF-irat*): the system first recognises its type (for example an invoice, a utility bill, a bank statement or a certificate), then extracts that type's fields on the chosen path and checks them in code (for example the tax number's check digit and the totals). A type that cannot be decided becomes a to-do.
- **An email** (*levél*): the system recognises its intent (the purpose of the email, for example that an invoice has arrived) and suggests the next step; its PDF attachments are processed as documents, traced back to the email; task proposals are made on request.

The **Processing settings** (*Feldolgozási beállítások*) card shows the settings and what each chosen value means. If nobody has saved settings for the batch yet, the card says ‘Default settings: if you do not change them, they are saved to the batch when a run starts.’ (*Alapbeállítás: ha nem módosítod, a futás indításakor ez mentődik a köteghez.*). Such a batch uses the application's **AI engine** (Settings › Processing, section 10.4) until its settings are saved. The settings:

- **Processing path** (*Feldolgozási út*), the first setting: which tool does the work. It is one choice of four; every path is followed by the same checks in code.
  - ‘Automatic (recommended) — JEV and GPT’ (*Automatikus (ajánlott) — JEV és GPT*): JEV recognises each document's type and each email's intent, and the document type's recommended path runs: S on Hungarian and foreign invoices, G on utility bills (because of the line items) and on every other document type (those only have a G path).
  - ‘JEV where possible — cheaper, no line items; GPT elsewhere (S)’ (*JEV, ahol lehet — olcsóbb, tételsorok nélkül; máshol GPT (S)*): code collects the possible values and JEV chooses among them. Only the eight invoice types (Hungarian and foreign invoices, six utility bills) have this path. Every other document type has no JEV path, so with this choice it runs on the G path (GPT + JEV), so that its data is still read; the pre-start overview then gives an OpenAI budget and says how many documents it is for. To run with no OpenAI call at all, check that the overview's OpenAI line says it is not called.
  - ‘GPT + JEV — with line items (G)’ (*GPT + JEV — tételsorokkal (G)*): GPT reads the data including the line items, and JEV checks each field. It costs more.
  - ‘GPT only, without JEV (OpenAI)’ (*Csak GPT, JEV nélkül (OpenAI)*): the run uses OpenAI only (and Azure recognition, if that is on). Earlier GPT answers are reused as with JEV (see **Earlier answers** below).
    - No JEV question can leave in such a run, not even an earlier JEV answer is reused. Should a step ask one anyway (a fault), it is not sent, and the item gets the to-do ‘The JEV question was not sent: this processing runs without JEV, on GPT only; check by hand’ (*A JEV-kérdés nem ment el, mert ez a feldolgozás JEV nélkül, csak GPT-vel fut; ellenőrizd kézzel*).
    - GPT recognises each document's type, about 0.001–0.002 USD per document. If its confidence cannot be measured, or the call fails, the document gets a to-do instead of a guessed type.
    - Every document runs on the G path: GPT reads the data, and the code checks it. Every extracted value must be printed on the document, otherwise the to-do ‘The extracted value is not printed on the document’ (*A kinyert érték nem szerepel az iratban*) appears. The check-digit, amount and required-field checks stay.
    - Without JEV's second opinion more errors can pass without a flag. Measured on the golden set on 2026-10-02: GPT recognised the type of 99 of 102 documents (JEV all 102) and stated its 3 errors confidently too. One of them already gets a to-do, and since 2026-10-02 a check in code flags a type that presumes a Hungarian issuer when GPT itself says the issuer is not Hungarian (‘The type (…) presumes a Hungarian issuer…’ (*A típus (…) magyar kiállítót feltételez…*)); on the golden set this caught one of the other two, and flagged none of the 99 correct types. The remaining error (a Hungarian company's invoice in English, taken as foreign) can still pass without a to-do; 27 of the 1010 fields of the 70 golden documents differed from the checked value.
    - GPT also recognises each email's intent, with the same questions as JEV: on the 96-email golden set it got 94 right and sent its 2 errors to manual review; about 0.0025 USD per email, from a budget of at most 0.07 USD. Routing and the task proposal work as with JEV. If the confidence cannot be measured, or the call fails, the email gets a to-do (‘The confidence of the email's intent cannot be measured; check it by hand’ / ‘GPT intent recognition failed …’; *A levél-szándék bizonyossága nem mérhető; ellenőrizd kézzel* / *A GPT-s szándékfelismerés nem sikerült …*). Its PDF attachments run as documents.
    - The run gets no JEV budget at all, so no JEV call can happen; the pre-start overview says ‘JEV: not called (switched off)’ (*JEV: nem hívódik (kikapcsolva)*).
  - A batch of emails only offers two choices, ‘With JEV (recommended)’ (*JEV-vel (ajánlott)*) and ‘GPT only, without JEV’, because the documents' path does not act on emails; their PDF attachments run as documents on the automatic path.
  - The saved settings keep the path and the use of JEV as two values, so batches and runs saved before this picker keep their meaning; an older batch without the use of JEV ran with JEV.
  - What the measurements say (Settings › Processing shows the full comparison): on the header fields of the golden set the two paths agree with the checked values about equally often (S: 942 of 953 fields, G: 940 of 953; the G measurement is older), the S path costs about a third to a sixth as much per document, and only the G path reads line items.
- **Earlier answers** (*Korábbi válaszok*), for JEV and GPT alike (until 2026-10-02 ‘JEV answers’, for JEV only): with ‘earlier answer may be reused’ (*korábbi válasz újrahasználható*), the earlier answer to the same question comes back free and instantly, so a rerun costs nothing and gives the same result; this is recommended for everyday work. A question is the same when the model, the instructions and the document's text are all the same; if any of them changes, a new, live call goes out. A change to a setting GPT is not sent (for example a JEV question or a description only JEV reads) does not make a GPT question new. A reused GPT answer is in the call log with cost 0 and the call it came from. ‘always a live call’ (*mindig élő hívás*) is for measurements, and the cost can grow up to the budget.
- **Azure recognition** (*Azure-felismerés*): ‘for weak scans’ (*gyenge szkennelésnél*) by default. If the local text recognition of a scanned document is weak, the system uses the more accurate, paid Azure recognition, from a budget of at most 0.02 USD per document; every call is in the call log. If the run's Azure budget runs out, the local text goes on and the document gets the to-do ‘Weak local recognition; Azure recognition was skipped because of the run's budget’ (*Gyenge helyi felismerés; az Azure-felismerés a futás kerete miatt elmaradt*). If Azure is not set up for the document or its call fails, the local text goes on too, with the to-do ‘Weak local recognition; Azure recognition is not set up for this document’ (*… az Azure-felismerés ehhez az irathoz nincs beállítva*) or ‘… Azure recognition failed’ (*… az Azure-felismerés nem sikerült*). With ‘off’ (*kikapcsolva*) only the local recognition runs.
- **Task proposal** (*Feladatjavaslat*) (emails only): ‘off’ (*kikapcsolva*) by default. When it is switched on, GPT makes a proposal for each email, which adds a cost per email.
- **Cost budget** (*Költségkeret*): the maximum amount per item and per provider that the system reserves when the run starts. It is an upper limit; the actual cost is usually lower.

To change them, click **Change** (*Módosítás*): the card shows a picker for each setting with its meaning, the budget, ‘Note (optional)’ (*Megjegyzés (elhagyható)*) and the **Save settings** (*Beállítások mentése*) button. Every save creates a new version; earlier runs keep their own settings. If someone else changed the settings in the meantime, a message tells you so; your choices are kept, so just save again. If the processing itself has changed since the settings were saved, or the batch still uses an earlier version of the processing (for example an invoice-only one with the type given in advance), a warning appears with a **Switch to the current processing** (*Átállítás a mostani feldolgozásra*) button: the settings are kept and a type given in advance is dropped, because the system recognises it. The **How the system works and what the settings mean** (*Hogyan dolgozik a rendszer, és mit jelentenek a beállítások*) link leads to Settings › Processing.

### 6.2 Readiness

Before you start, the **Run** (*Futtatás*) card shows anything that blocks the run. Blockers include: ‘The document batch has no items.’ (*Az iratkötegben nincs tétel.*), ‘The processing does not handle: …’ (*A feldolgozás nem kezeli: …*), ‘Missing source: …’ (*Hiányzó forrás: …*) and ‘The source content changed since it was added: …’ (*A forrás tartalma a felvétel óta változott: …*); the last two only for documents added before the system kept copies. For the others, ‘The copy kept when it was added is missing or damaged: …’ (*A felvételkori példány hiányzik vagy sérült: …*) blocks, while a changed or deleted original is only a warning: ‘The original file has changed since it was added; the copy kept then is processed: …’ (*Az eredeti fájl a felvétel óta megváltozott; a felvételkori példány kerül feldolgozásra: …*). While there is a blocker, the start buttons are disabled. Below the buttons, ‘What happens when the run starts’ (*Mi történik indításkor*) lists each service the run may call, with its budget and what it is for, for example ‘JEV up to 0.26 USD: type recognition and data extraction of 3 document(s); …’, ‘OpenAI up to 0.31 USD: 1 document(s) on the G path; …’; a service that will not be called is named too (‘OpenAI: not called, every document runs on the S path.’ (*OpenAI: nem hívódik, minden irat az S-úton fut.*)). A document whose type has not been recognised yet counts with the more expensive G path, because the type decides the path.

### 6.3 Trial run, live run, rerun

Below the **Run** card, **The batch's items** (*A köteg tételei*) lists what the batch holds, with **Add files** (*Fájlok hozzáadása*) and **Add a folder** (*Mappa hozzáadása*) (in a statement batch **Add statements**, *Kivonatok hozzáadása*); the list and adding are described in section 7.9. When added items wait for processing, a line above the list says how many (*N tétel vár feldolgozásra*) and carries the pending items' button too. The **Manage batch** (*Köteg kezelése*) menu in the batch header offers **Add documents** from any stage and opens the same form. While the add form is open, its last step is the page's one solid button.

- **Trial run…** (*Próbafutás…*): processing runs in full, with the same paid calls, but the result can only be viewed and downloaded, not released. Use it to try out new settings or a new document type.
- **Live run…** (*Éles futás…*): a person approves the result in the Result stage, once every item has finished and no to-dos are open. This is the valid result.
- **Rerun…** (*Újrafuttatás…*): repeats the run the batch's next step is about, in the same mode, as a new run, on all the batch's documents as they are now: the added ones too, the removed ones not. Useful after an error, a stop or a change of the settings.
- **Live run, pending items only (N)…** (*Éles futás, csak a függő tételek (N)…*) and **Trial run, pending items only (N)…** (*Próbafutás, csak a függő tételek (N)…*): shown once a run of that kind has finished some of the batch's documents while others wait, typically ones added later (section 7.9) or one that failed. The new run takes only those N documents, with their own maximum cost, so the documents already processed are not paid for again. The earlier runs, their to-dos, corrections and approval stay as they are; the new run's result is reviewed and approved on its own (section 8).

The highlighted button is always the one the batch's next step calls for; when the next step is ‘N new item(s) to process’, it is the pending items' button. Only one run at a time can be in progress on a batch.

### 6.4 The confirmation page

The three buttons do not start anything straight away; they take you to a summary page showing ‘Document batch’ (*Iratköteg*), ‘Items’ (*Tételek*), ‘Processing settings’ (with ‘default settings, saved to the batch when the run starts’ (*alapbeállítás, az indításkor mentődik a köteghez*) if none were saved), ‘Maximum cost’ (*Legnagyobb költség*) per provider, with the note ‘involves paid calls…’ (*fizetős hívásokkal jár…*) or ‘involves no paid calls’ (*nem jár fizetős hívással*), and the ‘What happens when the run starts’ list (section 6.2). At this point the system fetches the budget afresh (‘Refreshing the cost limit…’ (*A költségkeret frissítése…*)), and starting is disabled until it has done so. You start with **Start trial run**, **Start live run** (*Éles futás indítása*), **Start rerun** (*Újrafuttatás indítása*) or, for the pending items, **Start on the pending items** (*Indítás a függő tételeken*); **Cancel** (*Mégse*) takes you back. ‘Items’ is the number of documents the run will take: for a rerun, the batch's documents as they are now; for the pending items, only those. If the pending items were processed in the meantime, the page says ‘No item is pending any more…’ (*Már nincs függő tétel…*) and starts nothing. If the batch or its settings changed in the meantime, the page tells you (‘…We refreshed it; review it and start again.’ (*…Frissítettük, nézd át és indítsd újra.*)). Once started, you stay on the batch's Processing stage (under its case), whose Run card shows the run's progress; **Details of the latest run** (*A legutóbbi futás részletei*) opens the run page.

### 6.5 The run page

Its crumbs lead back to the case and its step (*Ügyek › the case › Feldolgozás*); a batch of no case leads to *Beállítások › Minden iratköteg*. Its main action, at the right end of the title row, is where the work goes on: **Review: N to-dos** (*Ellenőrzés: N teendő*) while it left to-dos, otherwise **Result and approval** (*Eredmény és jóváhagyás*).

- **Header:** the mode and time, the state (‘Queued’ (*Sorban áll*), ‘Running’ (*Fut*), ‘To-dos pending’ (*Teendő vár*), ‘Done’ (*Kész*), ‘Failed’ (*Hibás*) or ‘Stopped’ (*Leállítva*)), the processing settings, and who started the run.
- **Items:** for each item, its run state, the result and the number of to-dos. Clicking a to-do opens Review. The **Name:** switch shows the original or the unified names (section 5.2). Each item also shows its processing cost: one column per provider and model the run called successfully (for example ‘JEV (USD)’; the header names the model too, for example ‘JEV · jev-1.13.0 (USD)’, when a provider used several), and **Total cost (USD)** (*Költség összesen (USD)*). The **Columns** menu adds **From earlier answers (count)** (*Korábbi válaszból (db)*): how many of the item's questions were answered free from an earlier identical answer.
- **Cost** (*Költség*): first **Cost of the run** (*A futás költsége*), the run's actual cost over every provider. Below it, for each provider (JEV, OpenAI, Azure DI), the paid calls (how many failed), their actual cost and the models, then how many questions were answered free from earlier answers. A call whose cost is not known (for example a failed or interrupted attempt) is not counted as a cost; its reserved amount is shown apart as ‘Reserved, outcome unknown’ (*Lefoglalt, ismeretlen kimenetelű*), because the budget still counts it.
- **Planned and actual** (*Tervezett és tényleges*): for each provider, what the pre-start overview expected (‘expected’ (*várható*), ‘possible’ (*lehetséges*) or ‘not expected’ (*nem várt*)) against the actual cost. If a provider was called although the overview did not count on it, a warning says so. For a run started before the overview was saved with the run, only a note is shown.
- **Budget** (*Keret*), closed by default; its title gives each provider's share used (for example ‘Budget (JEV 13%, OpenAI 0%)’). Opened, it shows for each provider the committed amount against the budget: the cost of the completed calls plus the reserved upper bound of the calls not yet settled. It opens by itself when a budget is at least 80% used, or when the budget stopped something in the run (a to-do says so).
- **Job queue** (*Munkasor*): how many jobs are queued, running, done, failed (given up) or stopped.
- **Call log (raw model calls)** (*Hívásnapló (nyers modellhívások)*): an expandable list of the paid calls. It is empty if every answer came from the cache.
- **Stop** (*Leállítás*) (only while the run is in progress): asks for confirmation in a small card under it (*Megerősítés*), with **Cancel** (*Mégse*) and the action itself. Queued items stop at once; the item in progress stops after its next step. The run then ends as stopped, even if an earlier item failed. A run that has finished meanwhile is not stopped: supersede it instead.
- **Supersede** (*Leváltás*) (only on a finished live run that is not approved, when a later live run of the batch processed the same documents again and has finished): the to-dos of a live run that is not approved stay open until it is approved, even after a rerun. Superseding keeps the run as a stopped run and closes its own open to-dos (they are kept, not deleted); it cannot be approved afterwards. The box says how many to-dos close, links the later run, and warns if to-dos were already closed or documents corrected on this run (naming only what there is): that work stays with it and is not carried over. It asks for confirmation. Afterwards the page says who superseded it, when, and with which run; the batch's activity log records it too. The batch's Processing section lists every such run too (*Régebbi éles futások*), with its start, its open to-dos, a link to its page and the same button, with its confirmation. Since 200 an older **trial run** with open to-dos offers the same, when a later run of the batch (trial or live) processed the same documents again: superseding it only closes its to-dos, since a trial is never approved. A later trial run never supersedes a live run. When the list has a trial run in it, it is titled *Régebbi futások* and names each run by its kind (*Éles futás*, *Próbafutás*).
- **Result**, or for a live run **Result and approval** (*Eredmény és jóváhagyás*): takes you to the batch's Result stage.

While a run is in progress, the Processing stage shows a progress bar, and below it the ‘Runs of the document batch’ (*A köteg futásai*) table lists every run of the batch, with the actual cost of each run (**Cost (USD)**). Below that, **Cost of the document batch** (*A köteg költsége*) adds up every run of the batch per provider and model: paid calls, questions answered from earlier answers, and cost, with the total above the table.

## 7. Review

Before a run, the Review stage only shows the batch's documents (section 7.9). After a run, the workspace opens here.

### 7.1 The workspace

- **At the top:** the run picker (by default the run the batch's next step is about; you can type to search), the number of open to-dos, the ‘Run details’ (*A futás részletei*) link, the **Name:** switch (original or unified names in the item list, section 5.2) and the keyboard help.
- **On the left, the item list:** a search box (‘Search N items…’ (*Keresés N tétel között…*)) and a ‘to-dos only’ (*csak teendős*) checkbox. For each item you see the name (for an email, the subject), its state (‘to-do’ (*teendő*), ‘resolved’ (*rendezve*), ‘closed’ (*lezárva*), ‘not run yet’ (*még nem futott*), ‘Failed’…), and the ‘To-dos: N’, ‘N earlier to-dos’ (*N korábbi teendő*) and ‘unsaved’ (*mentetlen*) markers. The workspace opens at the first item that has a to-do. The earlier to-dos left by trial runs are hidden by default (a trial run cannot be approved, so they never close by themselves); when there are any, the ‘trial runs' to-dos too’ (*a próbafutások teendői is*) checkbox shows them, in the list and on the right. Your choice is remembered in this browser for the person working.
- **In the middle** is the page image of the document (from the copy kept when it was added; if the original file has changed or disappeared since, a note above the image says so), and **on the right** are the to-dos and the fields. You can drag the divider between them (or use ← / → on the keyboard); the ratio is remembered.

### 7.2 To-dos

- A to-do about one field is shown **at that field**, in red under its value, one sentence per reason (for example ‘Uncertain value: Gross amount (probability 0.58)’). A failed check of one field stands there too and names the field (for example ‘The tax ID format is not recognised: Supplier tax ID’ (*Az adószám alakja nem ismerhető fel: Szállító adószáma*)); a check of the whole document (totals, line items, dates) stays at the top. You settle it with the field's ✓ (section 7.4).
- At the top of the right-hand panel are only the to-dos about the whole document (for example ‘The supplier and the buyer have the same tax ID’ (*A szállító és a vevő adószáma azonos*) or an uncertain document type). The **Resolved** (*Rendezve*) button closes that one reason, under your name; the other reasons stay open.
- **Possible duplicate invoice:** when an earlier document in the system has the same invoice number and supplier, a box at the top shows the two documents' invoice number, supplier, date, amount and currency side by side; a differing value is highlighted, and the earlier document's name opens it in a new tab. Choose **Copy** (*Másolat*), **Modified version** (*Módosított változat*) or **Not the same invoice** (*Nem azonos*). The decision closes the to-do on both documents and the pair does not come up again; you can change it until the run is approved. Nothing is deleted: a copy is marked in Result and counts once in the totals.
- **Statements of the same days** (*Ugyanazon napok kivonatai*): when another statement books the same days of the same account, a box at the top shows the two side by side: file, period, source and number of lines. The better source replaces the other automatically when it covers the other's whole period (read by code with balances that check out, then extracted with balances that check out, then unchecked); the box says which one is valid and how many lines found their same line on it. When neither replaces the other (the same kind of source, or a period covered only in part), the statement gets a to-do and you choose: **This one is valid** (*Ez az érvényes*) or **The other one is valid** (*A másik az érvényes*). After a choice, **By the rule** (*A szabály szerint*) undoes it. The choice closes the to-do on both statements; you can change it until the run is approved. Nothing is deleted: the replaced statement stays with its run, but the reconciliation leaves it out, and the decisions on its lines move to the same lines of the valid statement.
- **Payments** (which statement line paid which invoice) are not decided on the review page but in a reconciliation batch (section 5.3). A ‘Possible payment’ to-do left open by an earlier run can be closed with **Resolved**.
- **Saving with Save correction does not close a to-do**; the field's ✓ does (the exception is correcting an email's intent, section 7.8).
- **Earlier to-dos** are reasons left open on the same document by an older run; they do not block the approval of this run. One about a field is shown at that field, in grey, as ‘from an earlier run: …’ (*korábbi futásból: …*), or ‘from N earlier runs: …’ when several runs left the same one; the field's ✓ closes it too, because a person has now verified the value. The ones about the whole document are at the bottom of the panel, closed: **Earlier to-dos about the whole document (N) — they do not block this run** (*Korábbi, egész iratra szóló teendők (N) — ezt a futást nem akadályozzák*), each with **Resolved**.
- **Checks on the saved data** (*Ellenőrzések a mentett adaton*): rules written in code (for example, whether the line items add up to the total) that run again, without paid calls, after you save a correction. A ‘Row N’ (*N. sor*) button takes you to the failing row. A check marked ‘advisory only, not a to-do’ (*csak jelzés, nem teendő*) does not open a to-do.

### 7.3 Fields, colours, boxes

- **Filter** above the fields: **To fix** (*Javítandó*) shows the fields with an open to-do in this run, **Uncertain** (*Bizonytalan*) the fields whose estimate is ‘To check’ or ‘Likely wrong’ and that nobody has verified or corrected yet, **All** (*Mind*) every field; each button shows how many fields it has. An item opens on To fix when it has something to fix, otherwise on All; the filter you choose stays for the next item while that item has fields in it. When the last field of the filter is done, the panel says so (for example ‘Nothing is left to fix on this item.’ (*Ezen a tételen nincs több javítandó mező.*)), with a **Next item with to-dos** (*Következő teendős tétel*) button. The keys move between the filtered fields (section 7.7).
- **Previous item / Next item** (*Előző tétel / Következő tétel*) at the top of the panel move through the items without going back to the list on the left.
- For each field you see its name, an ‘unsaved’, ‘verified’ (*ellenőrizve*) or ‘corrected’ (*javítva*) marker, the model's estimate as a percentage, and a source marker. The colour of the estimate is its confidence band: green ‘Confident’ (*Magabiztos*), blue ‘To check’ (*Ellenőrzendő*), red ‘Likely wrong’ (*Valószínűleg hibás*). A ‘–’ means there is no estimate. On the **GPT only, without JEV** path the estimate is GPT's: the probability of its answer, lowered to 50% when the field failed its field check; the tooltip says which (*GPT-becslés…*). GPT's estimates have their own band: green only from 98%, so a GPT field below 98% is ‘To check’ and shows under **Uncertain**. It is GPT's own estimate: GPT can be sure and still wrong. Below 98% on an accounting field (names, tax numbers, invoice number, dates, amounts) it also opens a to-do, ‘GPT is not sure enough of the value’ (*A GPT nem elég biztos az értékben*), so the document is not accepted automatically; on an address or another informational field it only shows the colour. When GPT's answer carries no probability at all (an answer saved before 2026-10-02, or another model), an accounting field with a value gets the to-do ‘GPT's confidence cannot be measured for this value’ (*A GPT bizonyossága nem mérhető ennél az értéknél*) instead of passing unchecked. With JEV neither to-do appears. A corrected field is always blue, because the estimate applied to the machine value. The colour is only a display aid, not a decision, and it does not prove that the value is correct.
- Source marker: ◉ the exact location is known, ◎ only an approximate location is known, ○ no location. Hover over the marker for an explanation.
- Fields with to-dos come first, then the ‘Likely wrong’ fields, then the rest.
- Below the selected field you see the ‘Source text:’ (*Forrásszöveg:*) with the page number; where relevant, a note that the value appears in several places; for a corrected field, the ‘Machine value:’ (*Gépi érték:*); and the ‘Other candidates:’ (*Más jelöltek:*) buttons.
- **On the image**, the value of the field being checked is highlighted in the colour of its band, line by line like a see-through marker, inside one thin frame drawn outside the text, so a value printed over several lines (an address) stays readable. Its other candidates have thin dashed boxes with a tag beside them; a candidate lying within the value shows only its tag. The image turns to the page of the field and scrolls the box into view. A dashed box is an approximate location (the line the machine picked from); a purple box is a location selected by hand. Selecting on the image is always on: clicking the words or dragging a rectangle selects text for the field being checked (section 7.4). The image bar has page buttons (‘‹ ›’) and zoom buttons (‘−’, the percentage to reset, ‘+’).
- If the document has no word layer (because of an earlier run or an old OCR result), the fields cannot be boxed. The interface tells you so; to get the boxes, run the processing again.

### 7.4 Checking and correcting values

Next to each field's value there are two buttons:

- **✓ (correct)** (*helyes*): saves this field's value, the one in the box (the machine value, or the one you typed, chose or selected), records that a person verified it, and closes the field's to-dos in this run, under your name. The field then shows **verified** (*ellenőrizve*) until its value changes. Only this field is saved; your unsaved changes to other fields stay in the working copy. If the box is empty, ✓ records that the document has no value for the field.
- **✗ (wrong, fix it)** (*hibás, javítom*): empties the field and puts the cursor in it, with the hint ‘Select the right value on the image, type it, or pick a candidate…’ (*Jelöld ki a helyes értéket a képen, írd be, vagy válassz jelöltet…*). Bring in the right value in one of the three ways below, then press ✓. Once a field has an unsaved change, **↺ (restore)** (*visszaállítás*) takes the place of ✗ and brings back the original value.

You can correct a value in three ways:

1. **Type** into the field's box. If you delete the value, it is saved as a ‘no value’ (*nincs érték*) correction. Amounts and quantities are shown and typed the Hungarian way: a comma is the decimal separator, and a space or a dot groups thousands. So `35,56` is 35.56, and `28.000`, `28 000` and `28000` are all 28 000. A form that could be read two ways, such as `28.5` for an amount, is not saved: the interface asks for a decimal comma (`28,50`) or a number without grouping (`28000`). A date can be typed in any common form: `2022-12-04`, `2022.12.04.`, `2022. december 4.`, `04.12.2022`, `4 Dec 2022`, `04-DEC-22`. A date whose day and month could be read two ways, such as `04/12/2022` (4 December or 12 April) or `04.12.22`, is not saved: the interface asks for the year first (`2022-12-04`) or the month's name (`4 Dec 2022`). After saving, the message names the value as recorded, for example ‘Saved. Recorded value: Net amount: 28 000’ (*Mentve. Rögzített érték: …*); a date is shown with the year first (`2022-12-04`).
2. **Choose another candidate:** the selected field's other candidates appear on the image in dashed boxes with a tag (‘72%’, ‘machine value’ (*gépi érték*), ‘possible location’ (*lehetséges hely*)), and as buttons in the panel. One click makes a candidate the field's value, as an unsaved correction.
3. **Select on the image** (always on when the document has a word layer): with the field being checked, click the words (clicking a word again removes it), or drag a rectangle. The system interprets the selected text according to the kind of field (date, amount, tax ID…) and shows the result (‘→ Field: value’). The **Enter into field** (*Beírás a mezőbe*) button, or Enter in the field's box, transfers the value. If the text cannot be interpreted, the interface says so (‘This text cannot be interpreted as a “…” value. Select something else.’ (*Ez a szöveg nem értelmezhető „…” értékként. Jelölj ki mást.*)). A selected date whose day and month could be read two ways is not entered either; the interface asks you to type it with the year first (*A kijelölt dátumban a nap és a hónap kétféleképpen is olvasható…*). The same kind of date found by the machine gets the to-do ‘Uncertain order of day and month’ (*A nap és a hónap sorrendje kétes*). The selected location is saved together with the correction.

### 7.5 Line lists

If the document has a line list (for example invoice line items or statement transactions), tabs appear at the top of the panel: ‘Fields’ (*Mezők*) and the name of the list with its number of rows; a ‘ •’ marker shows unsaved changes. The cells of the list can be edited (dates in any unambiguous form, stored as YYYY-MM-DD; amounts and quantities as in section 7.4), **Add row** (*Sor hozzáadása*) adds a new row, × deletes a row, and **Revert list** (*A lista visszaállítása*) discards your changes to the list. The column widths can be dragged as in the tables (section 3); they are remembered per list (for example for every statement's transactions), and **Reset column widths** in the list header returns the automatic widths. Clicking a row makes the image jump to where that row is. A row that failed a check is shown in red. The correction applies to the whole list; the machine list is kept unchanged alongside it.

### 7.6 Saving and conflicts

- The **Save correction** (*Javítás mentése*) button (or Ctrl+Enter) saves a new correction version; the machine value is kept alongside it. ‘Correction version: N’ (*Javítás verziója: N*) is shown at the bottom. You need a name to save.
- An unsaved correction (the working copy) is kept if you move to another item or reload the page. The browser warns you before you close the tab. Another browser tab cannot see it. **Discard all changes** (*Minden módosítás elvetése*) throws the working copy away. A change you make while a save is under way is kept: the save clears only what it sent, and the rest stays in the working copy for the next save.
- **Conflict:** if someone else saved to the same item in the meantime, your save does not silently overwrite their correction. Instead you see the message ‘Someone else saved this item in the meantime…’ (*Közben más is mentett erre a tételre…*) and a red box (‘A newer correction was saved for this item in the meantime (version N). Your working copy has been kept.’ (*A tételre közben újabb javítás került (verzió N). A munkapéldányod megmaradt.*)). **Apply to the new version** (*Alkalmazás az új verzióra*) moves your changes onto the new version; check them, then save again. **Discard working copy** (*Munkapéldány elvetése*) keeps the new version.
- Corrections on an approved run are locked (‘Corrections to an approved run are locked.’ (*A jóváhagyott futás javítása le van zárva.*)).
- **A case's quote** (stage D0): the line above the quote says whether everything is saved (‘Every change is saved at once.’, ‘Changes not saved yet’ (*Mentetlen módosítások*), ‘Saving…’, ‘Saved …’). If someone else saved the quote in the meantime, your change is not saved and not lost: ‘Not saved: someone else saved it meanwhile’ (*Nincs mentve: közben valaki más mentette*), and a table shows each of your changes beside the version saved now, marked where the other person changed it too. **Keep my changes** (*A módosításaim megtartása*) saves only your changes over theirs (what they changed and you did not stays theirs); **Drop mine, keep theirs** (*Az enyémet elvetem, a másiké marad*) asks once more. If the connection breaks while saving, ‘Whether it was saved is not known’ (*Nem tudni, mentődött-e*): your changes stay, **Save again** (*Mentés újra*) sends them. Unsaved changes stay while you look at another case and come back, but only until the page is closed or reloaded (they are never stored in the browser); the browser warns before that. The quote is not approved while it has unsaved changes (‘The quote has changes not saved yet’ (*Az ajánlatnak mentetlen módosításai vannak*)), and its head then says ‘save the changes first’ (*előbb mentsd a módosításokat*). If a newer version arrives while you type (someone else saved, or you come back to the case), the comparison opens where they changed the same field; elsewhere your typing simply goes on over their version. A change to a line they removed is marked ‘they removed it: yours cannot be applied’ (*a másik személy törölte: a tiéd nem alkalmazható*) and stays until you decide.

### 7.7 Keyboard shortcuts

The review works from the keyboard: when an item opens, the cursor is in its first field (under the filter) with the value selected, so typing replaces it.

| Key | What it does |
|---|---|
| Tab / ↓ | next field (its value selected); after the last field, Tab leaves the list as usual |
| Shift+Tab / ↑ | previous field |
| Enter | ✓: saves and verifies the field and goes to the next one; after the last field of the filter, to the next item with to-dos. If text selected on the image can be read as the field's value, the first Enter writes it into the box |
| typing / Delete | replaces / empties the value (Enter afterwards saves it; an empty value means the document has none) |
| Esc | brings back the original value of a changed field; otherwise it first clears the selection on the image, then leaves the box |

| outside a box: ↓ / ↑ (or j / k), n / p, Enter | next / previous field, next / previous item (n / p work on a line-list tab too), back into the field's box |

### 7.8 Reviewing emails

- **On the left is the email:** the subject, ‘From’ (*Feladó*), ‘To’ (*Címzett*), ‘Received’ (*Érkezett*), ‘Attachment’ (*Csatolmány*) and the text. Links cannot be clicked; instead, ‘link:’ and the host name are shown, and the full address appears when you hover over it. A notice warns you if intent recognition saw only the beginning of the email, or if the text may already have been cut off when it was downloaded.
- **On the right** are the to-dos with a **Resolved** button, and the **Detected intent** (*Felismert szándék*) with the model's estimate, or the marker ‘Corrected by hand (the machine said: …)’ (*Kézzel javítva (a gép szerint: …)*) / ‘Confirmed by hand’ (*Kézzel megerősítve*).
- **Correct the intent** (*Szándék javítása*): choose the correct intent. If it matches the current intent, the button reads **Confirm** (*Megerősítés*); otherwise it reads **Save correction**. When you save, the email's to-do for an uncertain intent is closed, and the **Suggested next step** (*Javasolt következő lépés*) (for example ‘Manual processing’ (*Kézi feldolgozás*), ‘Archive’ (*Archiválás*) or ‘Data extraction from the attachment (…)’ (*Adatkinyerés a csatolmányból (…)*)) is recalculated from the corrected intent.
- **Task proposals (only a person can accept them)** (*Feladatjavaslatok (elfogadni csak ember tud)*): shown only if task proposals are switched on in the processing settings. For each proposal you see the title, the action, the ‘Deadline’ (*Határidő*) and the ‘Assignee’ (only if the email states them word for word), and the quotes under ‘Evidence’ (*Bizonyíték*). Buttons: **Accept** (*Elfogadás*), **Reject** (*Elvetés*), and on an accepted proposal **Done** (*Elvégezve*) (recorded with your name and the time) and **Undo done** (*Elvégzés visszavonása*). Identical proposals are merged (‘N identical proposals merged’ (*N azonos javaslat összevonva*)). Proposals that failed the evidence check are listed in an expandable section, together with the parts that cannot be verified. No proposals are requested for emails to be archived (newsletters, notifications). Once you have decided on every proposal of an email, the to-do for its proposals (‘N task proposal(s) awaiting a decision’ (*N feladatjavaslat vár döntésre*)) closes by itself. If no proposal could be made, a ‘Task proposal failed (…)’ (*A feladatjavaslat nem sikerült (…)*) to-do is shown.
- **What the email may start** (since `v1.46.0`): when a process takes this email (an IT quote takes a quote request), its title with **Start a case from this email** (*Ügy indítása ebből a levélből*): the record read from the email and its attachments, each value with the part it came from, what the record still lacks, and the cases already started from it (*Ebből már indult ügyek*). Once a case is started, the button reads **Start another case from this email**. A process may start its case by itself (the IT quote does): once an email is read or corrected as its kind, its case starts within a minute, only once, and its paid steps (the IT quote's match) wait for a person's start.
- **Attachment detection** (*Csatolmányok felismerése*) and **Attachment data** (*A csatolmányok adatai*): a PDF attachment runs as a separate document in the batch. Its type is the one it was processed as: a foreign provider's receipt, for example, shows as a foreign invoice, because that is where its data was extracted. The ‘…: extraction result →’ (*…: az adatkinyerés eredménye →*) link takes you to the attachment's review view.
- A PDF attachment that cannot be read (corrupt, too large, or over the reading time or memory) is shown as ‘the PDF cannot be read’ (*a PDF nem olvasható*), and the email gets a to-do; the intent of the email is still recognised.

### 7.9 Managing documents

**The batch's items** (*A köteg tételei*) is the same list in Processing (below the **Run** card) and in Review: after a run in the expandable **The batch's items: add, open, download, remove** (*A köteg tételei: felvétel, megnyitás, letöltés, kivétel*) section below the workspace, before a run as the only content of Review. Its first line counts the items by state, each with its own mark: approved (*jóváhagyva*, green), processed live (*élesben feldolgozva*, orange: its approval is a person's turn), processed in a trial (*próbában feldolgozva*, a ring), being processed (blue), failed (red), pending (*függő*, a dark dot) and removed (*kivéve*, a dash). ‘Created from’ (*Létrehozva ebből*) says where the batch was made from: a folder, a mailbox, a statement batch, a file or files chosen by hand. In the list, **State** (*Állapot*) is the item's state, **Counted run** (*Érvényes futás*) the run whose result counts now (an approved live run first, then a live run, then a trial; a stopped or superseded run does not count), with a link to its page, and **Result** (*Eredmény*) and the open to-dos are that run's; the column menu adds the run's start (*Futás ideje*), the kind and the path.

**Adding** takes three steps, shown at the top of the form: **Choose** (*Kiválasztás*), **Check** (*Áttekintés*), **Add** (*Hozzáadás*). Choose **Given files** (*Megadott fájlok*: full paths, one per line, or **Browse…**) or **A folder** (*Mappa*, with **Include subfolders**, *Almappák is*, ticked by default; the output folder of the named copies is never taken). **Check what would be added** (*Áttekintés a felvétel előtt*) lists every document found, without writing anything: new (*Új*, ticked), already in the batch (*Már a kötegben van*), removed earlier (*Korábban kivett*: not ticked, tick it to restore it), or the same content as a file above. A file a live run of another batch has processed is marked (*máshol élesben feldolgozva*), so that it is not counted twice, and files that are not documents (for example images) are named and left out. Untick what you do not want, then **Add N document(s)** (*N irat hozzáadása*); the line below says what happened in the service's own counts (‘Added: …, already in the batch: …, restored: …’, and what was left out as unticked). The new documents wait for processing: the batch's next step becomes ‘N new item(s) to process’. Changing the choice after the check drops the check. A statement batch offers **Add statements** (*Kivonatok hozzáadása*) instead: the files (a folder, with **Include subfolders** if you tick it, or given files) are surveyed for the batch's own party and period, as when it was created, and what the batch already holds cannot be ticked again.

Each row has **Open** (*Megnyitás*) (in a new tab), **Download** and **Remove** (*Eltávolítás*). To remove several items at once, tick their rows and use **Remove N from the batch…** (*N tétel kivétele a kötegből…*) beside the selection. The ticks stay while you page, search or filter, and the action takes every ticked row, as many as the selection's count says; when some are not on the page shown, the count says how many (*ebből N nem ezen a lapon*). All of them are removed or none: if someone changed the batch meanwhile, nothing changes and the list reloads. A removal asks why (*Miért veszed ki?*): the reason is required, and the removal is recorded with your name (chosen at the top) and the time in the batch's log, once for all the items removed together. It takes the items off the batch's list; the files stay where they are. They stay out of the next runs, while a run already started keeps them. Tick **Removed items too** (*Kivett tételek is*, with their count) to see the removed items with who removed them, when and why; **Restore** (*Visszaállítás*) puts an item back (for several ticked removed rows, **Restore N**), and it takes part in the next run again. In Review, a run's item list marks a removed item ‘Removed’ (*Kivéve*), and its to-dos are not counted as the run's open to-dos. To process the added documents without paying for the others again, use the pending items' button (section 6.3). When another open live run of the batch has to-dos too (for example the run of the added documents next to the earlier one), Review says so above the workspace (*A kötegnek egy másik éles futása is nyitott, teendőkkel…*), with each such run's start, its to-dos and **Review it** (*Megnyitás*).

### 7.10 Word, Excel, text and CSV review

These documents open **Saved source** and **Native facts** instead of a PDF page. Word retains paragraph/table order and header/footer parts; Excel shows sheets, cell positions, empty and hidden content, and distinguishes formulas from their saved results without recalculating them. Text citations use exact character positions; CSV retains its rows, columns and literal text. The [reader guide](NATIVE_READERS.md) describes supported encodings and reading limits.

Each fact keeps its original **Machine proposal** beside the saved and editable value. Use its citation to inspect the source, edit the value if needed, then **Check and attach source** to bind an exact quote from a saved element. Unchecked quote text stays in the local draft. **Save corrections** saves the changes; **Confirm this fact** records the review. A late source check cannot restore a discarded draft.

Draft values and quote edits survive a reload. If another person saves first, your text is retained and saving is blocked until you explicitly review the refreshed correction. A draft for a different result remains separate. Reading coverage, extracted claims and factual correctness are different: a successful read does not prove that every needed fact was extracted or that a proposal is correct.

The summary above the facts names reading gaps in everyday words, one line per kind with a count (for example content kept only in the original, in 12 places), and the reason when an extraction stopped. The provider, the model and the raw reading messages are under **Technical details**. A fact's warnings (an unfilled template field, a value whose kind does not fit its property, a stale formula result) and its to-dos (for example JEV does not support fact 3) are shown as sentences; facts are counted from one.

In **Result**, the **Native facts** table joins the existing PDF views. Its **Source** column shows each cited text with a short place (a cell such as `Sheet1!B4`, `p. 2` for a PDF page, a pilcrow and the paragraph number for Word); the full citation data and the constant correctness column are hidden by default and can be shown under **Columns**. The machine states have everyday labels. Table downloads offer Excel, CSV and JSON with explicit row and column scope; **Full Excel batch** includes native facts and reading summaries alongside the PDF sheets. Approval binds to the result version actually displayed. A changed version must be reviewed again; approved runs lock corrections. Reopening a saved source or restarting the service does not itself request another model answer. Technical storage and recovery details are in [Native document processing](NATIVE_PROCESSING.md).

## 8. Result

- By default you see the result of the run the batch's next step is about: a run in progress, otherwise the oldest live run that waits for its review or approval, otherwise the latest run. If the batch has several runs, a run picker appears.
- **Several open live runs:** after a run over the pending items (section 6.3), a batch can have two live runs waiting, the earlier one and the one of the added documents. Each is reviewed, approved and downloaded on its own, the earlier one first; the batch's next step and a workflow step count as done only when none is left open. (A single result for the whole batch comes in a later version.)
- The views (only those that have data): **Emails** (*Levelek*), **Tasks** (*Feladatok*), **Documents** (*Iratok*), **Data points** (*Adatpontok*), **Line items** (*Tételsorok*), **Utility cost** (*Közmű-költség*) and **File names** (*Fájlnevek*). An email batch opens on Emails, any other batch on Data points.
  - ‘Documents’: one row per document (type, path, state, open to-dos and, for an email attachment, the subject of the email it came from) and one column per field. When a document is a possible or confirmed duplicate invoice, the ‘Duplicate’ (*Ismétlődés*) and ‘Duplicate of’ (*Azonos ezzel*) columns show it and name the earlier document. For an invoice, ‘Direction’ (*Irány*, 147) tells it from the own parties (section 10.3): incoming (*Bejövő*: an own party is the buyer), outgoing (*Kimenő*: an own party is the supplier, or it is an outgoing invoice), between own parties (*Saját gazdálkodók közti*), not an own party's (*Nem saját*) or unclear (*Eldönthetetlen*: the same party on both sides, which is usually a misread, or a name two parties fit). An outgoing invoice is never offered as the invoice a payment of a reconciliation batch paid.
  - ‘Data points’: one row per field (value, page, source text, location, whether it was corrected, and any to-do on the field).
  - ‘Line items’: the rows of the line lists.
  - Everywhere you see the valid data, that is, the machine value with any human correction applied. Clicking a document's name opens Review.
- Table rows can be selected with their checkboxes, and the selected rows can be downloaded on their own (section 3.1). The **Full Excel batch** (*Teljes Excel-csomag*) button puts all of the run's tables (including the utility cost) into one Excel file with several sheets.
- **Utility cost:** the gross amount of utility invoices per point of consumption and utility, month by month. An invoice that covers several months is split in proportion to the days. A cell shows the amount, or ‘missing’ (*hiányzik*: no invoice covers the month), ‘partial’ (*részleges*: part of the month is not covered) or ‘overlap’ (*átfedés*: two invoices cover it). An * marks a settlement invoice. Informational rows do not count towards the total. Clicking a cell shows its source invoices, each with an ‘open’ (*megnyitás*) link. The report counts a duplicated invoice (the same invoice number and supplier) only once, and says so, also while it is not yet confirmed; a pair you marked as ‘Not the same invoice’ counts twice.
- **File names:** copies of the documents under uniform, content-based names, for example `2026-09-12_SZAMLA_Minta-Kft_SZ-2026-001234.pdf` (date first, then the type, the partner and the identifier, without accents). The original files never change; the copies are exact byte-for-byte copies of the processed documents. The table shows each document's ‘New file name’ (*Új fájlnév*), whether it is ready or goes to review (‘Folder’ (*Mappa*)), and ‘Why to review’ (*Miért ellenőrzendő*).
  - A copy goes into the `ellenorzendo` (to review) subfolder when its name rests on something uncertain: the document did not finish processing, its type is unknown or uncertain, a field of the name is empty, or an open to-do concerns a field of the name. Correcting that field in Review makes the name certain.
  - The names follow the interface's language (section 2.2): from the English interface the same copy is `2026-09-12_HU-INVOICE_Minta-Kft_SZ-2026-001234.pdf`, the review subfolder is `to-check` and the manifest is `manifest.csv`.
  - **Download as ZIP** (*Letöltés ZIP-ben*) gives the copies and a manifest (`jegyzek.csv`: which original became which name, with its fingerprint). **Write to the output folder** (*Kiírás a kimeneti mappába*) puts the same into a new subfolder of the output folder (section 10.2); nothing there is ever overwritten. A document whose source file changed since it was added is left out and listed in the manifest as ‘skipped’ (*kimaradt*).
- **Approval:**
  - For a trial run, the interface states that the result cannot be released; that needs a live run.
  - For a live run, the **Approve and release** (*Jóváhagyás és kiadás*) button is active only once the run has finished and no to-dos are open; until then the interface tells you how many to-dos remain. It asks for confirmation in a small card that says what the release records.
  - A live run that a person stopped, that ended with an error or that a later live run superseded cannot be approved: the line says so (‘Stopped’, ‘Failed’, ‘Superseded’), and the Result tab reads ‘cannot be approved’ (*nem hagyható jóvá*). Rerun it in Processing. If the approval is refused because the run is not ready (for example a to-do opened meanwhile), the line gives the reason.
  - If an item was removed from the batch after the run started (section 7.9), the line says how many (‘N removed’, *N kivéve*, with an amber mark): the approval leaves them out of the released result, and their to-dos do not count. If someone removes another item in the meantime, the approval is refused until you have seen the new count.
  - After approval, ‘Released: approved by …, …’ (*Kiadva: jóváhagyta …, …*) is shown. An item removed or restored later does not change a released result. Approval locks the run's field corrections, intent corrections and task-proposal decisions; you can still mark an accepted task as ‘done’ (*elvégezve*). Approval cannot be undone from the interface. Downloads remain available afterwards.

The table columns are ‘Time’ (*Időpont*), ‘Action’ (*Művelet*), ‘Case or batch’ (*Ügy vagy iratköteg*), ‘Detail’ (*Részlet*) and ‘Run’ (*Futás*).

### 10.1 Mailboxes

Mailbox download brings in emails from the Outlook running on this computer. Since `v1.70.0` the section's pages are built the one way (section 2):

- **The section's page**: the **Schedules** (*Ütemezések*) are the one list (search, grouping by frequency, state or the last download's outcome); a schedule's name opens its own page. In the title row, **New schedule** (*Új ütemezés*) is the main action, and **Download once, in a new case** (*Egyszeri letöltés új ügyben*) opens a new mailbox case's form, where a one-off download of the last days or of a date range is counted and started (until `v1.70.0` this page offered a date range it could only count). Below, the **Downloads** (*Letöltések*): the state of every download, the number of new emails, the document batch created and any error, grouped by state or by who started it. Known Outlook errors (for example ‘Outlook is not running on this computer…’ (*Az Outlook nem fut ezen a gépen…*)) are shown in the interface language.
- **A new schedule's page**: ‘Mailbox address’ (*Postafiók címe*) (you can enter several, comma-separated, exactly as they appear in Outlook; addresses under ‘Previously used:’ (*Korábban használt:*) can be added or removed with one click), ‘Folder’ (*Mappa*) (comma-separated), ‘with subfolders’ (*almappákkal*), the ‘Number of days’ (*Napok száma*) it looks back (a schedule reads the last days, never a date range), ‘At most this many emails (0 = no limit)’ (*Legfeljebb ennyi levél (0 = nincs korlát)*) and the ‘Frequency’ (*Gyakoriság*: every 15 minutes, every 30 minutes, hourly, every 4 hours, daily). **How many emails? (free)** (*Hány levél? (ingyenes)*) previews how many emails fall in the period, how many are new and how many were already read in (these are skipped). **Cancel** (*Mégse*) or **Save schedule** (*Ütemezés mentése*), which opens the schedule's page.
- **A schedule's page** (with ← Previous and Next →): what it reads, when it runs next and how its last download ended; its ‘Frequency’ and ‘On: it downloads by itself’ (*Bekapcsolva: magától letölt*) are saved together with **Save** (*Mentés*); **Delete** (*Törlés*, at the left; it asks for confirmation; its downloads so far stay in the log). Below, **Its downloads** (*A letöltései*). The schedule records who last changed it and when; a change and a deletion are also written to the service log with the active user's name. A schedule only runs while the worker is running and Outlook is open.
- The worker does the download, and document processing waits in the meantime. The new emails become a document batch, but no paid run starts on its own.
- A message from the Sent Items folder is not asked about its intent, because that question reads the sender's aim: only its attachments are processed, it gets no task proposal, and its review page says ‘Sent message: its intent is not asked’ (*Elküldött levél: a szándékát nem kérdezzük*).

### 10.2 Work folders

A work folder (a watched folder) is a folder that the worker checks at the frequency you set; it turns new documents into a document batch with a case of the Documents process around it (since 2026-10-28), or adds them to the existing batch. For each folder you can set: ‘Name’, ‘Full folder path’ (typed, or chosen with **Browse…** as in section 4), ‘Active’ (*Aktív*), ‘Include subfolders’ (*Almappák is*), the packaging (‘One shared batch’ (*Egy közös köteg*) or ‘Daily batches’ (*Napi kötegek*)) and how often to ‘Check’ (*Átnézés*). The batch gets the default processing settings; you can change them on the batch. Since `v1.70.0` the folders are the one list (search, grouping by state, packaging, frequency or the last check's outcome), each opening its own page with ← Previous and Next →: **Add work folder** (*Munkamappa hozzáadása*) in the title row opens a new folder's page; a folder's page saves it with **Save** (*Mentés*; **Cancel** (*Mégse*) puts back what is saved) and removes it with **Remove** at the left (it asks for confirmation; its batches and documents stay). If there are unsaved changes, leaving the page asks for confirmation. On a saved folder, **Check now** (*Átnézés most*) in the title row checks it immediately; a file that is still being written is left for the next check. The system only reads the source folder, and no paid run starts on its own.

Below the list, the **Output folder** (*Kimeneti mappa*) card sets where the content-named copies of a run are written (Result › File names). It is saved on its own with its **Save** button; an empty field clears it. It cannot be inside a watched work folder or contain one (the watcher would take the copies in again), and a work folder cannot be saved inside it either.

### 10.3 Own parties

An own party (*saját gazdálkodó*) is a company, an association or a person whose money is reconciled: the buyer of the incoming invoices and the holder of the bank accounts and cards. A reconciliation batch is one party's (section 5.3). The system proposes the parties from the processed documents, by code and free of charge: the buyer's tax number and name on the invoices, and the holder's name at the top of a statement's first page. It does not decide on its own; nothing is fixed, and every batch follows a change at once.

- **Suggestions from the data** (*Javaslatok az adatokból*): a new party with its invoices, its tax numbers, its name variants (*névváltozat*: how its name is printed as the buyer; the legal form, the numbers and the order of the words do not count) and its accounts; or what an existing party gains. Check the name of a new party (it can be edited), then **Accept** (*Elfogadás*) or **Add** (*Hozzáadás*); **Accept all N** (*Mind elfogadása*, it asks for confirmation) accepts them at once. **Not own** (*Nem saját*, it asks for confirmation) dismisses a suggestion that names no own party of yours, for example a buyer misread from a ticket.
- **The parties**: each with its invoices and their span, the span of its statements, its tax numbers and accounts, and its name variants (folded when there are many). **Rename** (*Átnevezés*); **Move to…** (*Áthelyezés ide…*) moves a tax number, a name variant or an account to another party, back among the unassigned ones (proposed again) or among the dismissed ones; **Merge into…** (*Összevonás ezzel…*, it asks for confirmation) merges two parties (its batches follow); **Delete** (*Törlés*, it asks for confirmation) works only for a party no batch uses, and its names and accounts are proposed again.
- **Accounts and cards** of a party: each with its details (kind, bank, currencies, the days it was open) and its statements, or ‘no statement yet’. **Register a bank account or card** (*Bankszámla vagy kártya felvétele*) adds one before any of its statements is processed: its number (*Számlaszám*, an IBAN or a domestic number; the two forms are one account), its kind (*Bankszámla* or *Kártya*: a credit card with its own statement; a debit card's purchases are on its account's statement), its bank and the days it was opened and closed (optional) and its currencies (*Pénznemek*, for example ‘HUF, EUR’ for an account with two currencies). **Details** (*Adatok*) edits them, also for an account found on statements. A registered account has to be covered in a reconciliation batch even without a statement, so its missing months show and its invoices are never ‘No payment found’ for want of its statements. Another party's account cannot be registered here; move it first.
- **Data status by month** (*Havi adatállapot*, folds open): the party's months (by default this year up to the last closed month; *Hónaptól*, *ig* change it) as rows, its accounts and currencies as columns, its invoices last. A month of an account is ‘OK’ (*Rendben*: statements cover it, their balances check out and their run is approved), ‘Awaiting approval’ (*Jóváhagyásra vár*), ‘Balances do not check out’ (*Nem stimmel az egyenleg*), ‘Part of the month’ (*A hónap egy része*), ‘No statement’ (*Nincs kivonat*) or ‘–’ when no statement is expected (before the account was opened, which is its first statement's day when not registered; after it was closed; the running month). Two marks may stand beside it: ‘two statements’ (*két kivonat*: two statements book the same days and neither replaces the other, so their lines may count twice until you choose the valid one on the review page) and ‘balance break’ (*egyenleg-szakadás*: the opening balance is not the previous statement's closing balance). ‘N replaced’ (*N leváltva*) means that a better statement replaced N statements of the month, which the reconciliation leaves out. The invoices column gives the month's invoices of the party and how many of them are not in an approved run.
- **Unassigned** (*Besorolatlan*): a tax number or a name seen on too few invoices, or one like more than one party: **Give to…** (*Besorolás ide…*) a party or **A new party** (*Új gazdálkodó*), or **Not own**.
- **Not own (N)** (*Nem saját*): the dismissed ones; **Undo** (*Visszavonás*) proposes them again.

Which party an invoice belongs to: its buyer's tax number first (so the company's contact person printed as the buyer does not move it), then a known name variant, then a name that holds every word of exactly one party's variant, a misread letter allowed. An invoice that names its own supplier as the buyer is a misreading and counts as having no party.

### 10.4 Processing

At the top, **AI engine** (*AI-motor*) sets which AI the processing asks, for the whole application:

- ‘JEV and GPT (recommended)’ (*JEV + GPT (ajánlott)*), the default: JEV recognises each document's type and each email's intent, and chooses or checks the extracted values; GPT extracts where a type's path needs it. The golden-set measurements use this setting.
- ‘GPT only, without JEV’ (*Csak GPT, JEV nélkül*): GPT recognises the type and the intent and extracts the data, and the code checks each value against the document. There is no JEV cost, but each document costs more OpenAI, and a value whose GPT confidence cannot be measured becomes a to-do.

The choice applies to every new processing setting: a new batch, a batch whose settings were never saved, a mailbox download, a watched folder and a workflow step without its own choice. A batch whose settings were saved keeps its engine (change it on the batch's **Processing settings** card, section 6.1), and a run keeps the engine it started with. **Save** (*Mentés*) is active only while the choice differs from the saved one; the card's corner shows who set it and when.

The engine a run used is shown with its results, as a small neutral mark, ‘AI engine: GPT only’ (*AI-motor: Csak GPT*) or ‘AI engine: JEV and GPT’ (*AI-motor: JEV + GPT*): on the release line beside **Approve and release**, so an approval of a GPT-only result is made knowingly; on the Review section's bar; and beside an email's recognised intent. Hovering over the mark says what that engine did. An intent taken over from another run has no mark, as that run's settings may differ.

How the system works: what happens to a PDF document and to an email, what it needs, the steps, the result, what the person has to do, the default cost budget, every possible value of every setting with its meaning and budget, and **The paths compared** (*Az utak összevetése*): what the S and G paths do, whether they read line items, which services they call, their typical cost per document, their agreement with the golden set, which document types they work on and when each is better, with the source and date of the numbers. Nothing can be changed here; this is a read-only description.

Below the processing's description, **Bank files the system reads** (*A rendszer által olvasott banki állományok*, 146) lists every kind of bank file the system takes, as on the statement batch's form (section 4).

### 10.5 Users

If the list is not empty, changes can only be made with a name on the list, and the batch owner is also chosen from it.

### 10.8 Operations

**Operations** (*Üzemeltetés*; until `v1.59.0` System) holds the running system's state:


- **Version** (*Verzió*): the running release version and commit (a fixed, identified state of the code in version control), and how long the service has been running. New code only takes effect after the service is restarted. ‘The running code contains uncommitted changes.’ (*A futó kód commitolatlan változást tartalmaz.*): the running code includes changes that have not been committed yet, so it is not exactly a released state. ‘The commit is unknown…’ (*A commit nem ismert…*): the service was started without version control.
- **A newer version is running** (*Újabb változat fut…*, a banner above the header on every page): the service was restarted with new code or the interface was rebuilt since this browser tab was loaded, so the tab still shows the old interface. **Reload** (*Újratöltés*) loads the new one; unsaved corrections are kept. The tab checks every minute and whenever you switch back to it. A restart of the same code shows no banner.
- **Worker** (*Feldolgozó*): ‘Running’ or ‘Not running’ (*Nem fut*), and the job-queue counts (queued, in progress, done, stopped, given up); since `v1.61.0`, where the service configuration lets more than one worker run (`configs/service.json` `workers`), how many of them run (‘2 of 3 workers’ (*2 / 3 feldolgozó*)). **Stop** asks for confirmation, and every worker stops after its item in progress. They can only be restarted with the start script, which starts as many as the configuration allows.
- **Database backup** (*Adattár-mentés*): a verified copy of the database (batches, runs, corrections, decisions). It runs automatically every day at the configured time, and a copy also goes to a second location (for example a network drive). The panel's state is ‘OK’ (*Rendben*), ‘Attention’ (*Figyelem*) or ‘Error’ (*Hiba*), with the location of the local backup and of the copy below it. The ‘Internal documents’ (*Belső dokumentumok*) row shows the backup of the developer's local notes and has nothing to do with daily work. **Back up now** backs up immediately. If the last successful backup is older than the configured number of hours (36 by default), a warning appears.
- **Dependency audit** (*Csomag-ellenőrzés*): when the third-party program packages were last checked for known security flaws, and the result. It also warns when a newer patch release of the Python version the system runs on is out (the update itself is done by hand). The daily backup runs the check once a week. ‘Attention’ (*Figyelem*) means the check is missing, older than a week or incomplete; ‘Error’ (*Hiba*) means a known vulnerability was found, which the developer has to fix.
- **JEV version** (*JEV-változat*, since 200): the system asks one fixed version of JEV, so its answers do not change by themselves. The daily backup looks once a day which version the provider's “latest” name points to. ‘Attention’ (*Figyelem*) means a newer version is out (the system keeps asking the fixed one; switching is the owner's decision, with a measurement), or that the look is missing or older than three days.
- **Calls with an uncertain outcome** (*Bizonytalan kimenetű hívások*): paid calls of which it is not known whether the provider carried them out, for example because the answer did not arrive in time after the request was sent. Until one is settled, its run's budget counts it at its maximum cost and the step is not repeated. Settle it with the actual cost from the provider's console (or none) and a note; it asks for confirmation. The cost must be between 0 and 100 USD, here and on the command line. Only a call whose outcome is uncertain can be settled: a call still in progress cannot, because it may still finish and cost money.
- **All runs** (*Minden futás*): every run of every batch in one table.

### 10.9 Partners

**Partners** (*Partnerek*, since `v1.44.0`) is the shared register of the outside parties the processes deal with: customers (*Vevő*), suppliers (*Szállító*), the insured (*Biztosított*) and brokers (*Alkusz*); one partner may play several roles. It starts empty: only a person records a partner. Since `v1.59.0` the own parties (section 10.3) stand in the same list, by name, with the role **Own party** (*Saját gazdálkodó*) and their first tax number; such a row leads to Own parties, where it is still edited (‘An own party is edited under Own parties.’), and no partner can be given that role. With a role chosen in the filter, a line above the list names the processes whose cases deal with a partner of that role (the own parties' role: the reconciliations and the bank statements).

- **The list**: search by name, tax number or email (*Keresés*), filter by role (*Minden szerep*), and show the retired ones too (*A visszavontak is*). Open a partner to see its values.
- **New partner** (*Új partner*): a name and at least one role are needed; the tax number, email, phone, address and a note are optional; **Record the partner** (*A partner rögzítése*) saves it. A partner with the same tax number, or without one the same name, as another partner is refused, and the page offers to open that one instead.
- **Save as a new version** (*Mentés új változatként*): every change is kept as a new version, and **Versions** (*Változatok*) lists the earlier ones with who changed them and when. If someone saved the partner meanwhile, your save is refused so that it does not overwrite theirs.
- **Retire** (*Kivonás*) instead of deleting; **Restore** (*Visszaállítás*) brings it back.
- **Proposals from the documents read** (*Javaslatok a beolvasott iratokból*, after **Show the proposals**): the suppliers of the incoming invoices and the buyers of the outgoing ones that are not yet partners, never an own party (section 10.3). Since `v1.70.0` they are the one list (search, sort, grouped by the first role they were seen in, every proposal, not only the first 200). Nothing is recorded by itself: a row's **Accept** (*Elfogadás*) fills a new partner's form with the proposal's values, to check and save.

A case's page shows the partners its process names: an IT quote's **Request** (*Kérés*) tab shows the request's customer. If the register already has a partner that seems to be the same, **Link that one** (*Azt kösd hozzá*); otherwise **Record as a partner** (*Felvétel partnerként*) records the request's values and links the new partner. A linked partner shows ‘Linked’ (*Hozzákötve*).

A case step whose result a person approves (an IT quote's **Approval** (*Jóváhagyás*) tab) says where its approval stands (stage D0). While it is not approved, you may give it back instead with **Return it** (*Visszaadás*): the reason is required, the button asks once more, and ‘Returned by …, …: …’ (*Visszaadta: …, …. Indok: …*) shows who, when and why until the next approval; the step keeps waiting for its approval. An approved result goes out of date by itself when a step it builds on gets a new result (for example the match is redone): ‘Out of date: an earlier step it builds on changed: …’ (*Elavult: egy korábbi lépés, amelyre épül, megváltozott: …*) names the step; check the result and approve it again. Nothing else runs by itself.

### 10.10 Processes

**Processes** (*Folyamatok*, since `v1.45.0`; since `v1.59.0` a page of its own for each) first lists every process with what it is for. Each process has its own menu item under **All processes** (*Minden folyamat*) and its own address, and its page has five tabs:

- **Description** (*Leírás*): what the process is for, how a case of it starts (from an email's intent, from a batch, or by hand), its steps (what each does, whether it starts by itself or a person starts it, which steps it waits for, whether it may be left out), what it produces and the golden sets it is measured on.
- **What it uses** (*Amit használ*): the product, the price list, the letter frame, the output, the send mode and the output template, each chosen from a list that holds only what fits its step (an IT quote's document offers the quote, not the insurance offer); an empty list says where its values come from. Each shows the value in use (*Érvényben*), the file's value (*A csomagfájl értéke*) and where it comes from: ‘Own value’ (*Saját érték*) or ‘From the file’ (*A csomagfájlból*). An insurance process's tariff follows from its product (‘From the product’ (*A(z) Termék szerint*)): it cannot have a value of its own; set the product instead, and a case keeps the active version of the tariff its product names. The send mode offers only the two ways a person still sends from (the output folder, a draft in Outlook); the real send stays a decision of the owner.
- **Rule values** (*Szabályértékek*): the values the process's steps let it set: how many requested items one proposal matches (only fewer than the file's), how many lines a quote holds, the unit a forint and another currency's amounts are rounded to, and how long the model's letter paragraph may be. A cost limit is never one.
- **Partner roles** (*Partnerszerepek*): the roles the process's partners play and the step they come from (section 10.9).
- **Examples** (*Példák*): the process's example material (section 4.2).

A line above the values says who may make a value active (by default the person who saves it) and that a case keeps the values it started with: a change reaches only the cases started after it. Since stage D0 a case also keeps the price list's and the own template's version and the rule files as they were at its start (a newer price list version reaches only the cases started after it, unless you move a case's quote to it with **Price from version N** (*Árazás a(z) N. változatból*), or choose a template beside the quote's download, which is then used at its active version); the first line of its **History** (*Előzmények*) names them (‘It keeps from its start: …’ (*Az induláskori változatokkal fut végig: …*)).

- Click a setting to open it: type or choose a **New value** (*Új érték*) with a note and **Save as a draft** (*Mentés piszkozatként*); a draft changes nothing. For a rule value, **Try it on earlier decisions** (*Kipróbálás a korábbi döntéseken*), or **Preview** (*Előnézet*) on a draft, shows how many of the process's earlier decisions would come out differently, with examples; nothing is written and no AI is asked. A key no earlier decision has read (a quote's lines) says so. **Make active** (*Élesítés*) makes the draft the process's value; **Use the file's value** (*Vissza a csomagfájl értékére*, it asks for confirmation) sets the own value aside. **Versions** (*Változatok*) list every value with its note, who saved or activated it and when.

### 10.11 Products

**Products** (*Termékek*, stage D) shows what an offer is built from. A segmented control switches between its lists: **Products** (*Termékek*), **Tariffs** (*Díjtáblák*, since `v1.59.0`, section 10.12), **Rules** (*Szabályok*) and **Condition documents** (*Feltétel-iratok*), each with its count; the Products and the Tariffs lists name the processes that use each (*Használja*). Every product, rule, document and tariff is kept as versions: a draft (*Piszkozat*), the active one (*Éles*), a superseded one and a retired one (*Kivont*), which stays readable, so a case started with it keeps it. A set of them (for now the invented insurer, `configs/golden_products.json`) is added with `python -m jav.cli product-set --install --maker <name>`: everything arrives as a draft.

- Click a product's name to open it: its **Cover modules** (*Fedezeti modulok*, the base cover and the extensions it needs), its **Condition documents** with the days they are in force and their clauses, its **Rules** with the clause each was read from (‘KB-ÁF-2026 · 6.1. pont · 3. o.’), the **Tariff** (*Díjtábla*) its premium is computed by, and its **Versions** (*Változatok*). Click a rule's title to see what it decides below the list.
- A rule opens as a **decision table** (*Döntési tábla*): a row per line, the facts it compares (‘> 5 000 000 HUF’, ‘ezek egyike: …’, ‘bármi’ for any value), a double rule, then the outcomes it gives (a verdict, a required protection class, a deductible, measures, warnings). The first row that fits decides; a row a missing fact leaves open makes the outcome ‘not known’. Under it, the document, page and clause it was read from (*Honnan*) and the quoted words.
- A **condition document** opens with its clauses, their pages and titles, and the rules read from each clause.
- A draft shows **What keeps it from being made active** (*Ami akadályozza az élesítést*): for a rule, its own checks against the fact catalogue (a fact it does not read, a value of the wrong unit or currency); for a product, the release manifest (a document or rule it names that is still a draft, a rule citing a clause the document does not have, a module it needs that it does not have, a tariff with no active version). When nothing does, **Make version N active** (*A(z) N. változat élesítése*, it asks for confirmation) is the view's one solid button. A product is made active by another person than its maker: its maker sees ‘You made this version: another person makes it active.’ An active version can be **retired** (*Kivonás*, it asks for confirmation).

**Proposals** (*Javaslatok*, stage D) asks a model for the rules of a condition document's file. Choose the document version the rules will cite, the product whose cover modules the proposer is told, the file (**Browse…**), and the proposer: the **stand-in** (*Helyettesítő*: the invented insurer's rules, free, for trying) or **GPT, within a budget** (*GPT, költségkereten belül*), with an OpenAI budget and, if you tick it, a JEV budget for JEV to judge each proposal; the button shows the most the run can spend. The file is read page by page; a page marked internal (a line "Internal") is never sent, and the run lists such pages. Each run lists its proposals: where each was read from (page and clause), the **code's check** (*Kódos ellenőrzés*: ready, numbers to confirm, or blocked), JEV's mark (supported, to check, contradicted, not asked) and the decision. A proposal opens with its decision table, the clause it was read from, **What blocks it** (*Ami akadályozza*), **What to look at** (*Amit érdemes megnézni*) and where each of its numbers stands (in the quote, on the cited page, on another page, written as a word, following from a stated number, not in the document, read by text recognition). **Accept as a draft rule** (*Elfogadás vázlat szabályként*, it asks for confirmation) is the view's one solid button only when nothing blocks the proposal and you have ticked every number the document does not print; **Reject** (*Elutasítás*) needs a reason; **Correct the rule (as a record)** (*A szabály javítása (rekordként)*) takes the rule's record and checks it again. An accepted or corrected proposal becomes a draft rule under **Rules**, made active as usual. The same is possible from the command line: `rule-propose`, `rule-proposals`, `rule-proposal-decide`.

### 10.12 Tariffs

**Tariffs** (*Díjtáblák*, stage D; since `v1.59.0` a list of the Products page, as a product brings its tariff, and the old address leads there) lists the tariffs the premiums are computed from, each with the days it is in force, its currency, its cover modules and its policy minimum. A tariff opens as **How the premium is computed** (*Így számolódik a díj*), in the order the itemised calculation follows: (1) each cover module on the units of its level, the basis (a sum insured) times the rate per thousand, then its factors in their order (a module may price only some units: burglary prices no building); (2) each line rounded; (3) a module's lines summed, its minimum, the modules summed; (4) the total factors (the payment frequency); (5) the total rounded and the policy minimum. A missing factor, a value no row of a factor's table takes, a cover start the tariff is not in force on or an amount in another currency gives no total: never a default. **Factors** (*Szorzók*) shows each factor's table (‘≥ 3 → × 0,9’). Making a draft active and retiring work as for the products.

### 10.13 Letter frames

**Letter frames** (*Levélkeretek*, since `v1.59.0`) are the texts of the letters that go with a printed document: the **Covering letters** (*Kísérőlevelek*: an insurance offer's and a renewal's, in Hungarian) and the **Quote reply letters** (*Árajánlat-válaszlevelek*: the reply to a quote request, a text in Hungarian and one in English; its first paragraph is written for each request). Each frame shows its text field by field (its subject, its greetings with and without a name, its paragraphs, its closing), the processes that use it, and whether the system's text (*a rendszer szövege*) or its own text counts (‘its own text: version N’ (*saját szöveg: N. változat*)).

- **Change the text** (*Szöveg módosítása*) opens the frame's fields; a blank line starts a new paragraph. The markers, such as `{{total}}` or `{{policyholder}}`, are filled in by the system from the document, and the form lists the ones you can use. **Save as a draft** (*Mentés piszkozatként*) saves only what you changed, with a note; a draft changes no letter. A text is refused, with every problem named, when a field is empty or too long, a one-line field holds a line break, or a marker is not closed or names no value of the documents.
- **Make version N active** (*A(z) N. változat élesítése*) makes the draft the frame's text, by the same rule as a process's own values: the cases that start from then on use it, and a case keeps the text it started with. **Back to the system's text** (*Vissza a rendszer szövegéhez*, it asks for confirmation) sets the own text aside for the cases that start after. **Versions** lists every text with its note, who saved it and when.
- A frame is not added or removed here: the processes name the frames the system comes with.

### 10.14 Defaults

**Defaults** (*Alapértékek*; until `v1.60.0` the read-only Rules (*Szabályok*)) lists how the system decides on its own: one row per kind of decision it records, with what it decides, the values it decides with, the version of its rule files in use and how many decisions it has made. Choose a decision's title to open its sheet below the table.

On the sheet each value shows whether the rule file's value counts (‘The file's value counts.’ (*A fájl értéke érvényes.*)) or the installation's own value, its default (‘The installation's own value: version N’ (*A telepítés saját értéke: N. változat*), with the file's beside it).

- **Set a default** (*Alapérték megadása*) opens a form that fits the value: a percentage or a gap in percentage points as a percentage (between 0 and 100), a whole number or an amount, yes or no, one of a list (an email's next step), a set of ticks (document types, fields, warning signs), each intent's next step, or an ordered list of codes, one a line (the product catalogue's levels, its verdicts best first). **Try it on earlier decisions** (*Kipróbálás a korábbi döntéseken*) shows how many earlier decisions read the value and how many would have come out differently, with examples; the ones a process's own value decided are named apart, as a default does not reach them. Nothing is written and no AI is asked. **Save as a draft** (*Mentés piszkozatként*) saves it with a note; a draft changes nothing.
- **Make version N active** (*A(z) N. változat élesítése*) makes the draft the default, by the same rule as a process's own values (section 10.10). From then on the cases that start use it, and so does the work outside a case; a case keeps the values of its start, and a process's own value of the same key still goes over the default. **Back to the file's value** (*Vissza a fájl értékére*, it asks for confirmation) sets the default aside. **Versions** list every value with its note, who saved it and when.
- A value that changes a paid request or a budget (the paid text recognition, a run's item budget) stays the file's, and the sheet says so. Every other value may have a default, even the product catalogue's levels and verdicts and the digits compared in a tax number: a wrong one there can break the products' rules or the tax number check, so try it first.
- A measurement (`python -m jav.cli measure`) reads the rule files, not the defaults; it says when the installation keeps defaults.

## 12. What the interface does not do

- There is no login and no password. The **Who is working?** name only records the author; it is not a permission.
- It can only be reached from this computer; the service rejects requests from other computers and from other websites.
- It never starts a paid run on its own, and neither do work folders or mailbox schedules.
- It does not modify or delete source files. Deleting a batch or removing an item only takes the files off the list.
- It does not open links in emails.
- The model's estimate, and agreement between two models, do not prove that a value is correct: that is why the interface asks for a human check.
- Restoring from a backup and restarting the worker are not done in the interface (Technical details).

## Technical details

**Starting and stopping** (from the project root, in PowerShell; installation: [SETUP](SETUP.md)):

```powershell
.\scripts\dev.ps1 start    # local service (127.0.0.1:8930) + the configured workers (one by default) in the background; parts already running are not restarted
.\scripts\dev.ps1 status   # whether the service and the worker are running, and how many jobs are waiting
.\scripts\dev.ps1 stop     # the worker exits after the item in progress; the service stops immediately
```

- **Address:** `http://127.0.0.1:8930/`. The interface calls the `/api/...` endpoints. `/api/health` supplies the data for the Version card (version, commit, uncommitted changes, start time) and for the newer-version banner (`ui_build`: a fingerprint of the UI build served now, read on every request). The clickable endpoint list (`/api/docs`) is switched off. The security settings are described in the [security notes](../SECURITY.md).
- **Service logs:** `runs\logs\api.log` and `runs\logs\worker.log`; the start script's output: `runs\dev\*.log`.
- **Command-line equivalents:** `python -m jav.cli worker-status`, `worker-stop`, `backup`; for a paid call with an uncertain outcome: `calls-uncertain`, `calls-resolve <id> [--cost USD] --note N`. Restoring from a backup is done by hand, with the service stopped: [SETUP 6.](SETUP.md). The daily backup is started by Windows Task Scheduler (`scripts\backup-task.ps1`).
- **The bracketed reason of a JEV to-do:** `budget_exceeded` (the item's budget ran out), `uncertain_attempt` (the outcome of an earlier paid attempt is unknown and has to be settled by hand); any other value is an error or a timeout of the service.
- **Configuration files** (details: [configuration files guide](CONFIGS.md)):
  - the processing and its settings: `configs/recipes.json` (internally still called recipes; the UI offers only the active `processing`); their explanatory texts and the comparison of the paths: `configs/recipe_help.json`; moving old packages onto the processing: `python -m jav.cli processing-migrate [--write]`;
  - confidence bands (`confidence_bands`, 0.9 and 0.5 by default), backup (`backup`: time, number of copies kept, `max_age_hours`) and folder restriction (`restrict_paths`, `JAV_API_ROOTS`): `configs/service.json`;
  - Hungarian names of fields and document types: `configs/field_labels.json`; email intents: `configs/intents.json`; task-proposal actions: `configs/email_tasks.json`.
- **Data stored in the browser** (per viewer, not stored in the database): name `jav.actor`, language `jav.ui-language`, appearance `jav.appearance`, column visibility `jav.table.<table>.cols`, column widths `jav.table.<table>.widths` (a line list: `jav.table.list.<field>.widths`), the image/panel ratio `jav.review.split` (on the line-list tab `jav.review.split.list`); the working copy, per tab: `jav.drafts` (sessionStorage).
- **Source code:** the interface is in `ui/src/` (views: `views/`, review: `review/`, labels: `labels.ts`, English translation: `i18n/en-*.json`); the service is `jav/service/api.py` with its endpoint modules `jav/service/api_*.py`, the table columns are in `jav/app/datasets.py`, the next step in `jav/app/work_views.py`. Structure: [architecture](../ARCHITECTURE.md), section 8.
